## 虚拟dom

虚拟 DOM（Virtual DOM）是 UI 结构的 **JavaScript 对象描述**。其核心逻辑是通过对比对象差异来减少昂贵的真实 DOM 操作。

### 核心工作流程

- **创建阶段**：框架（如 React/Vue）将代码编译成描述 UI 的 JS 对象。

- **状态更新**：当数据变化时，重新生成一个新的虚拟 DOM 树。

- **Diff 算法**：对比新旧两棵虚拟 DOM 树的差异（O\(n\) 复杂度）。

- **Patch 阶段**：将计算出的差异（补丁）一次性同步到真实 DOM。

### 为什么需要虚拟 DOM？

- **跨平台能力**：虚拟 DOM 本质是普通对象，脱离了浏览器限制，可以映射为 iOS/Android 原生组件或 SSR（服务端渲染）字符串。

- **性能保证**：虽然手动优化真实 DOM 可能更快，但虚拟 DOM 提供了一种无需手动操作、性能“下限”极高的方案。它将多次 DOM 修改合并为一次，有效减少了浏览器的重排（Reflow）和重绘（Repaint）。

- **开发体验**：开发者只需关注状态（State），无需处理繁琐的 DOM API，提高了代码的可维护性。

react中虚拟dom的实现（其实想问之前和现在的做法）

React 的虚拟 DOM 实现主要经历了从 **Stack Reconciler** 到 **Fiber Reconciler** 的架构演进：

---

### 过去：Stack Reconciler \(React 15 及以前\)

在 React 16 之前，虚拟 DOM 的更新是基于**递归**实现的。

- **实现方式**：采用深度优先遍历（DFS）对比新旧虚拟 DOM 树。

- **同步执行**：一旦开始 Diff，就会同步递归到底，期间无法中断。

- **痛点**：当组件树过于庞大时，JS 引擎长时间占用主线程，导致浏览器无法处理动画、输入等高优先级任务，造成页面卡顿（丢帧）。

### 现在：Fiber Reconciler \(React 16\+\)

为了解决同步递归的阻塞问题，React 彻底重构了底层架构，引入了 **Fiber**。

- **数据结构**：Fiber 节点将“树”结构转换成了**带指针的链表**（包含 `child`、`sibling` 和 `return` 指针）。

- **实现方式（增量渲染）**：

    - **可中断**：将更新任务拆分为多个小的“工作单元”。

    - **优先级控制**：利用 `requestIdleCallback` 类似机制（Scheduler），在浏览器空闲时间执行更新。高优先级任务（如点击事件）可以打断低优先级的 Diff 任务。

- **双缓存技术**：内存中同时存在 `current`（当前显示）和 `workInProgress`（正在构建）两棵 Fiber 树。构建完成后，直接切换指针完成替换。

---

react是怎么实现状态更新的（包含状态合并）

在现代 React（Hooks \& React 18\+）中，状态更新的核心在于 **Fiber 架构下的异步调度**与 **Lane 优先级模型**。

---

### 触发更新与 Update 对象

当你调用 `setCount` 时，React 内部会执行以下操作：

- **创建 Update 对象**：包含本次更新的具体操作（如直接值或函数 `c => c + 1`）以及优先级标记（Lane）。

- **挂载链表**：将该 Update 挂载到该 Hook 对应的 `memoizedState.queue` 链表末尾。

### 状态合并机制 \(Batching\)

React 为了性能，不会在每次调用 `setState` 时立即触发渲染。

- **自动批处理 \(Automatic Batching\)**：在 React 18 中，无论是在合成事件、`setTimeout`、`Promise` 还是原生 DOM 事件中，多次状态更新都会被合并为**单次重新渲染**。

- **合并原理**：React 会在当前事件循环（Event Loop）微任务执行前，持续收集所有的 Update，只在最后发起一次渲染任务。

### 计算最终状态 \(Render Phase\)

在渲染阶段，React 遍历 `updateQueue` 链表：

- **函数式更新**：如果传入的是函数，React 会将前一个 Update 的计算结果作为参数传给下一个函数，从而确保状态的连续性。

- **优先级抢占**：如果有一个高优先级更新（如用户输入）进来，React 会中断当前的低优先级计算，先处理高优先级任务。

### 协调与双缓存 \(Reconciliation\)

- **生成 WorkInProgress 树**：React 在内存中克隆当前的 Fiber 树，并在其上应用计算出的新状态。

- **Diff 算法**：对比 `current` 树和 `workInProgress` 树的差异，并打上副作用标记（Flags）。

### 同步提交 \(Commit Phase\)

当 `workInProgress` 树构建完成，React 进入 Commit 阶段：

- **同步执行**：这是一个不可中断的过程。

- **DOM 更新**：根据之前打上的标记，一次性将差异应用到真实 DOM。

- **指针切换**：将 `current` 指针指向新生成的树，完成界面更新。

---

### 总结

现代 React 的更新是**异步可中断**的。它通过 **Update 链表** 收集变更，通过 **Lane 优先级** 决定顺序，并利用 **自动批处理** 减少无效渲染，最终实现高性能的 UI 同步。

react如何防止注入攻击（可以猜想面试官想考哪些东西，在回答0

在 React 中，防止注入攻击（主要是 XSS）主要依靠其**内置的自动转义机制**，但面试官通常会通过此问题考察你对“非安全性操作”及“现代 Web 攻击手段”的深度理解。

以下是核心回答逻辑：

---

### 默认自动转义（内置防御）

React 会对所有在 JSX 中渲染的字符串进行自动转义。

- **机制**：在渲染前，React 会将所有的值转换为字符串。

- **防御点**：它会将 `<`、`>` 等特殊字符转义为 HTML 实体（如 `&lt;`）。这意味着即使后端返回了 `<script>alert(1)</script>`，React 也只会将其作为普通文本渲染，而不会被浏览器执行。

### 核心考点：绕过机制的风险点

面试官通常想听你是否了解哪些情况会导致防御失效：

- `dangerouslySetInnerHTML`：
这是 React 留出的“后门”，用于直接渲染 HTML 原生字符串。如果数据来源不可信且未经过滤，会直接导致 XSS。

    - *防御方案*：必须使用 **DOMPurify** 等库对 HTML 字符串进行清洗（Sanitize）。

- **非法的 **`href`** 属性**：
`<a>` 标签的 `href` 属性如果接受 `javascript:alert(1)` 这种格式，点击时仍会触发脚本执行。

    - *防御方案*：对 URL 进行协议检查，只允许 `http:`、`https:` 或 `mailto:`。

- **服务端渲染 \(SSR\) 注入**：
在 SSR 场景下，如果直接将数据脱水（Dehydration）并注入到页面的 `<script>` 标签中作为全局变量（如 `window.INITIAL_DATA = ${JSON.stringify(data)}`），攻击者可以通过闭合标签 `</script><script>...</script>` 进行注入。

    - *防御方案*：使用 `serialize-javascript` 库进行序列化，转义关键字符。

eact怎么防止多次调用函数

在 React 开发中，防止函数（尤其是高开销逻辑或 API 请求）被多次调用，通常根据**触发场景**分为三种核心策略：

---

### 针对“组件内逻辑”的防重：`useMemo` \& `useCallback`

这是为了解决 React 重新渲染（Re\-render）导致函数被重新创建并触发的问题。

- `useCallback`：缓存函数引用。当父组件重新渲染时，如果依赖项没变，传递给子组件的函数引用不变，配合 `React.memo` 可防止子组件重复执行该函数。

- `useMemo`：缓存计算结果。只有当依赖项变化时，才重新计算高开销的值，避免重复计算。

### 针对“用户交互”的防重：防抖 \(Debounce\) \& 节流 \(Throttle\)

防止用户在短时间内频繁点击按钮或输入，导致事件处理函数被密集调用。

- **防抖 \(Debounce\)**：动作停止一段时间后才执行（如：搜索框输入）。

- **节流 \(Throttle\)**：在固定时间间隔内只执行一次（如：滚动加载）。

- **实现建议**：由于 React 渲染机制，建议使用 `useRef` 配合 `lodash` 的防抖函数，确保在组件生命周期内该函数引用是稳定的。

JavaScript

```Plain Text
const debouncedSearch = useRef(
  _.debounce((query) => fetchData(query), 500)
).current;
```

### 针对“副作用执行”的防重：`useEffect` 依赖项

这是面试官常考的“如何防止 `useEffect` 在每次渲染时都运行”。

- **正确配置依赖数组**：只有在数组中的变量变化时才执行。

- **清理函数 \(Cleanup\)**：利用 `return () => ...` 取消上一次未完成的请求或清除定时器，防止旧的逻辑在后台多次叠加执行。

### 构造函数的核心定义

在现代前端开发中，构造函数主要用于**初始化对象**。虽然 ES6 引入了 `class`，但其本质依然是构造函数的语法糖。

说一下构造函数

---

### `new` 操作符的执行过程

当我们执行 `new Constructor()` 时，发生了以下四个步骤：

1. **创建新对象**：在内存中创建一个空的简单 JavaScript 对象（即 `{}`）。

2. **原型链接**：将该新对象的 `[[Prototype]]`（即 `proto`）指向构造函数的 `prototype` 属性。

3. **绑定 ****`this`**** 并执行**：将构造函数内部的 `this` 绑定到该新对象，并执行构造函数内部的代码（为新对象添加属性）。

4. **返回对象**：如果构造函数没有返回非原始值（Object, Array 等），则默认返回这个新创建的对象。

### ES6 Class 的最新特性

目前我们更多地使用 `class` 语法。与传统函数写法相比，它具有以下特性：

- **严格模式**：类体内部默认执行 `use strict`。

- **私有属性**：使用 `#` 前缀声明私有变量（如 `#count`），在类外部无法直接访问。

- **静态块**：支持 `static {}` 初始化块，用于复杂的静态属性初始化逻辑。

### 与普通函数的区别

构造函数首字母通常大写（约定俗成），且必须通过 `new` 调用。在 ES6 中，如果尝试直接调用 `class` 而不使用 `new`，引擎会抛出 `TypeError`，这比 ES5 的普通函数模拟更具安全性。
