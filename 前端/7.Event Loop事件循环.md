# 7\.Event Loop事件循环

## **Event loop 执行顺序**

Event Loop 执行顺序如下所示：

- 首先执行同步代码，（同步代码属于特殊的宏任务）

- 当执行完所有同步代码后，执行栈为空，查询是否有异步代码需要执行

- 执行所有微任务

- 当执行完所有微任务后，如有必要会渲染页面

- 然后开始下一轮 Event Loop，执行宏任务中的异步代码，也就是setTimeout中的回调函数

虽然setTimeout写在Promise之前，但是因为Promise属于微任务而setTimeout属于宏任务，所以Promise会先执行。

## **微任务与宏任务**

微任务于宏任务的根本区别是微任务属于es语法\(es委员会制定标准，各个浏览器引擎都可以实现自己的实现方式\)，而宏任务就是浏览器的原生方法方法。宏任务是相对于微任务的一个概念同时包含同步和异步任务。

- 微任务包括process\.nextTick，promise，MutationObserver, aysnc/await。

- 宏任务包括script，ajax, setTimeout，setInterval，setImmediate，I/O，UI rendering。

- 宏任务中包括了script，浏览器会**先执行一个宏任务**，接下来有异步代码的话才会先执行微任务

## **微任务与宏任务与dom渲染**

在有dom变化的js进程中，先执行同步代码，然后执行微任务然后**渲染dom**，然后在执行宏任务。

注意改变dom本身是同步\(dom本身已经生成也可以访问到\)，渲染dom需要等同步代码和微任务执行完成后才会进行。

**浏览器判断是否需要渲染**（根据帧率、页面活跃度、是否有改动决定）。如果需要，则进入“渲染阶段”，该阶段步骤（大致顺序）如下：

- 处理输入事件（touch、wheel、click 等）

- 执行 **requestAnimationFrame 回调**（用于 JS 更新动画状态）

- 样式计算（重新计算 CSS 规则）

- 布局（回流/重排）

- 更新 CSS 动画/过渡，并触发相关事件（如 `animationstart`）

- 处理 **IntersectionObserver 回调**（通常在布局之后、绘制之前）

- 绘制（重绘）

- 合成（GPU 层合并）

渲染完成后，若有**空闲时间**，则执行 **requestIdleCallback** 队列中的任务（低优先级工作）。

## **异步执行顺序**

```JavaScript
async function async1 () {
    console.log('async1 start');
    await async2();
    console.log('async1 end');
}

async function async2 () {
    console.log('async2');
}

console.log('script start');

setTimeout(function () {
    console.log('setTimeout');
}, 0);

async1();

new Promise(function (resolve) {
    console.log('promise1');
    resolve();
}).then(function () {
    console.log('promise2');
})
script start
async1 start
async2
promise1
script end
async1 end
promise2
setTimeout
```

- 1\-5都是同步操作按执行顺序执行

- 2\-3 await只会阻断自己下边的函数并且加入到微任务（优先级高于Promise），右边、上边的的函数都是立即执行的（如果函数是异步的，正常加入异步队列）。

- 4 Promise在创建时是同步操作，

- 6\-7 await后面的函数优先级高于Promise

- 8 setTimeout一般都是最后一个执行



```JavaScript
async function async1() {
    console.log('async1 start');
    await async2();                
    console.log('async1 end');
}
async function async2() {
    await async3(); 
    console.log('async2');
}
async function async3() {
    console.log('async3');
}
console.log('script start');
setTimeout(function() {
    console.log('setTimeout');
}, 0)
async1();
new Promise(function(resolve) {
    console.log('promise1');
    resolve();
}).then(function() {
    console.log('promise2');
}).then(function() {
    console.log('promise3');
});
console.log('script end');
script start
async1 start
async3
promise1
script end
async2
promise2
async1 end
promise3
setTimeout
```

为什么promise2在'async1 end'前面,可以把async1看成

```JavaScript
new Promise(function(resolve) {
    console.log('async1 start');
    console.log('async3');
    resolve();
}).then(function() {
    console.log('async2');
}).then(function() {
    console.log('async1 end');
});
```
