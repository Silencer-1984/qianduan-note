# 03 浏览器与渲染

## 渲染流程

六步：

1. 解析 HTML → **DOM 树**（字节 → 字符串 → token → Node → 树，一句话带过）。
2. 解析 CSS → **CSSOM**。
3. DOM + CSSOM 合成**渲染树**，只含要显示的元素（`display: none` 的不进）。
4. **布局 / 回流**：算出每个节点的位置和大小。
5. **绘制**：生成绘制指令，光栅化。
6. **合成**：按图层交给 GPU 拼成最终画面。

CSS 和 JS 的下载是并行的，DOM 边解析边构建。

## 阻塞渲染

- **CSS 阻塞渲染**：没有 CSSOM 就生成不了渲染树，首屏必须等 CSS 下载完。但 CSS 不阻塞 HTML 解析（只阻塞它后面 JS 的执行）。
- **JS 阻塞解析**：脚本可能改 DOM，所以解析到 `<script>` 默认停下来。
- 优化手段：首屏关键 CSS 内联、非关键 CSS 异步加载、`<script>` 用 `defer` 或 `type="module"`。
- “把 script 放 body 底部”是老做法，现在放 `head` 加 `defer` 更好——不阻塞解析，还按顺序执行。

## 重绘与回流

**一句话**：改样式不一定会重排，但重排一定会重绘。

- **回流（Reflow）**：发生在**布局阶段**。元素的大小、位置、几何属性变了，浏览器要重新算一遍每个盒子在哪、多大。改宽高、改字体、增删 DOM、改定位或浮动、window resize 都会触发。
- **重绘（Repaint）**：发生在**绘制阶段**。只有外观变了（如 `color`、`background`），不影响布局。

**成本**：回流远比重绘贵。改一个父节点的子节点，很可能带着父节点一起连锁回流。

**怎么减少（能说三条就够）**：
- 位移/缩放用 `transform`，别改 `top/left`（transform 走合成，不触发布局）。
- 要隐藏用 `visibility: hidden`，别用 `display: none`（后者会把元素从布局里摘掉，触发回流）。注意 `visibility` 仍占位、仍会被读到。
- 批量改样式：先 `display: none` 离线改完再显示，或合并成一次读写，避免强制同步布局。
- 补一句就够：动画用 `requestAnimationFrame`；少用 `table` 布局；选择器从右往左匹配，别写太深。

**被追问时**：回流在布局阶段、重绘在绘制阶段；重绘不一定回流，回流必定重绘。

## defer 与 async

- 普通 `<script>`：遇到就停下 HTML 解析，下载并执行完才继续，会阻塞渲染。
- **async**：异步下载，下完**立刻执行**，执行时会打断解析；多个 async 谁先下完谁先跑，**顺序不确定**。适合完全独立的脚本——埋点、统计、广告。
- **defer**：异步下载，等 HTML **解析完**、`DOMContentLoaded` 之前，**按文档顺序**依次执行。适合要操作 DOM、彼此有依赖的脚本，比如主应用。**实际项目里基本只用 defer。**

**加分一句**：`<script type="module">` 默认就是 defer 行为。

## 事件流

三个阶段：

1. **捕获**：从 `window` 往下走到目标元素。
2. **目标**：事件到达目标。
3. **冒泡**：从目标往上回到根。

大部分事件会冒泡，`focus` / `blur` 不会（用 `focusin` / `focusout` 代替）。

- `stopPropagation()`：只阻止**继续传播**，当前元素上其余监听函数照样执行。
- `stopImmediatePropagation()`：连当前元素上后面的监听也一起掐掉。
- 别随手阻止冒泡：埋点、全局点击统计都是挂在 `document` 上的委托，别人一停你就收不到。

## 事件委托

不在每个子节点上绑，而是绑在父级，靠冒泡拿到真正触发的元素。

- 子节点动态增删不用重新绑，也省掉一堆监听器。
- 坑：`e.target` 可能是子节点里的 `<span>`，判断身份要用 `closest()` 或 `contains()`，别直接比 `===`。
- React 17 之前把所有事件都委托到 `document`，17 之后挂到根容器上。

## 存储

| | 容量 | 生命周期 | 随请求发送 | 读写 |
|---|---|---|---|---|
| `cookie` | 约 4KB | 可设过期时间 | **会**，同域每个请求都带 | 同步，字符串 |
| `localStorage` | 5–10MB | 不主动删就一直在 | 不会 | 同步，字符串 |
| `sessionStorage` | 同上 | 关闭标签页即清空 | 不会 | 同步，字符串 |
| `IndexedDB` | 按磁盘配额，很大 | 不删就一直在 | 不会 | **异步**，能存对象 |

- `cookie` 现在基本只用来放会话标识，不存业务数据。三个安全属性要会说：`HttpOnly`（JS 读不到，防 XSS 偷 token）、`Secure`（只走 HTTPS）、`SameSite`（防 CSRF）。
- `localStorage` 是同步的，塞大 JSON 频繁读写会卡主线程。
- token 放哪是个取舍：放 `localStorage` 怕 XSS，放 `HttpOnly` cookie 怕 CSRF，没有免费的午餐。

## 为什么操作 DOM 慢

不是“JS 引擎和渲染引擎两个线程通信”——DOM 和 JS 现在就在同一个渲染主线程上。真实开销是：

- JS 对象和 DOM 之间有一层绑定，每次访问都要过桥；
- 改 DOM 会触发样式重算、布局重算，一次改动可能带出一串回流；
- **读写交替**最坑：读完 `offsetHeight` 马上写样式，浏览器被迫立刻同步布局，一次循环里重复几十次就是灾难。

所以做法是：批量读、批量写，布局值先存变量，能一次插完的别分两次。

## 几万个 DOM 怎么不卡

- **虚拟滚动**：只渲染可视区，滚到哪换哪，非可见区完全不建。
- **分片插入**：用 `requestIdleCallback` 或 `setTimeout` 一批批插，别一次卡死主线程。
- **`DocumentFragment`**：先攒在碎片里，最后一次性挂上去，只触发一次布局。
- 循环里别读布局属性，那是最容易写出来的性能事故。

## 性能优化

**一句话**：性能优化就三件事——**少下载、少等待、少干活**。

被问到别急着报清单，先判断卡在哪一段，再从这三个方向里挑两个能说出数据的手段。

**加载慢**（用户等页面出来）：

- 少下载：压缩、图片按需（懒加载、webp）、tree shaking、按路由拆分。
- 少等待：hash 文件名 + 长缓存、CDN、`preload` 关键资源。
- 少干活：关键 CSS 内联、JS 用 `defer`、首屏不需要的都往后放。

**用起来卡**（页面在手上不跟手）：

- 少干活：虚拟列表、计算丢进 Worker、别在循环里读布局。
- 少变化：动画只用 `transform` / `opacity`（走合成不触发布局）；`will-change` 用完要撤，滥用会让图层爆炸、内存暴涨。
- 少抢占：防抖节流、长任务切片，别让一个同步任务把主线程占满。

**指标就记三个**：LCP 看加载，CLS 看稳定，INP 看交互。

**案例怎么讲**：`原来 X 秒 → 做了什么 → 变成 Y 秒 → 代价是 Z`。没有数字的优化，等于没做。
