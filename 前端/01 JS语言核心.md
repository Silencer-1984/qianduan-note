# 01 JS 语言核心

## 类型判断

**`typeof` 的结果，说白了就三种情况**：

| 输入 | 返回 | 坑 |
|---|---|---|
| 基本类型（除 null） | 各自类型名 | — |
| `null` | `'object'` | 历史遗留 bug，别当对象用 |
| 引用类型（除函数） | `'object'` | 数组、Date、正则全是 `object` |
| 函数 | `'function'` | — |
| `NaN` | `'number'` | NaN 自己也不等于自己 |

所以：**`typeof` 只适合判基本类型和函数**。判数组用 `Array.isArray`，判具体类型用 `Object.prototype.toString.call(x)`，它最准，能分出 `[object Array]` / `[object Date]`；自定义类的实例统一给 `[object Object]`，所以它分不出你的类。

**`instanceof`**：顺着原型链找，所以只能判引用类型，基本类型永远 `false`。

**`typeof null` 为什么是 object**：早年用低位存类型标记，`000` 表示对象，而 null 是全零，被误判了。这个 bug 一直没修，因为修了会挂掉老代码。

## 类型转换

目标只有三种：字符串、数字、布尔。

- **加号是特例**：一方是字符串 → 另一方也转字符串拼接；否则两边都转数字。`'a' + +'b'` 是 `'aNaN'`，因为 `+'b'` 先变 `NaN`。
- **其他算术运算**（`- * /`）：只要一方是数字，另一方就转数字。
- 对象转原始值走 `ToPrimitive`：先 `valueOf` 再 `toString`。所以 `[] == false` 成立——`[]` 先变 `''` 再变 `0`。

**`==` 与 `===`**：

- 项目里**一律用 `===`**，唯一允许 `==` 的场景是 `if (x == null)`——一行同时判掉 `null` 和 `undefined`。
- 两个反例：`NaN == NaN` 是 `false`；`null == undefined` 是 `true`，但 `null == 0` 是 `false`。

## 箭头函数

四条限制：

1. **没有自己的 this**，定义时就继承外层作用域。所以回调里用它最省事，也不会丢 this。
2. **不能 `new`**，因为它没有 `[[Construct]]`。
3. **没有 `arguments`**，要用就上 rest 参数。
4. **不能做 generator**（不能用 `yield`）。

另外：**不能当对象方法用**，`obj.arrow()` 里的 this 指向外层，不是 `obj`。

## this

一句话原则：**`this` 在调用时确定，箭头函数例外（定义时确定）**。

四条优先级，从高到低：

1. `new Foo()` → this 指向新对象
2. `bind` / `call` / `apply` → 显式指定
3. `obj.foo()` → 指向 `obj`（谁调用指向谁）
4. 直接 `foo()` → 非严格模式 `window`，严格模式 `undefined`

三个典型陷阱：

- **方法被"摘"出来调用**：`const f = obj.foo; f()` → this 丢了，变成 window。绑定事件回调、`setTimeout(obj.foo)` 都踩这个。
- **`setTimeout` 里的 this 永远是 window**，因为本质是 window 调用的。经典题：

```js
var name = 'tom'
const a = {
  name: 'jack',
  say() { console.log(this.name) },        // jack
  wait() {
    setTimeout(function () { console.log(this.name) })  // tom
  }
}
```

解法就两句：换成箭头函数，或 `.bind(this)`。

- **箭头函数 `bind` 无效**，因为它根本没有自己的 this。同理，**`bind` 只认第一次**，`f.bind(a).bind(b)` 还是 a。

两处加分点：

- DOM 事件处理函数里，this 指向绑定的元素。
- `new` 有个例外：**构造函数里 `return` 一个对象，this 就被顶掉了**，返回的是那个对象。所以 `new` 不一定拿到 this。

## 闭包

**定义**：函数能访问并持有外层作用域里的变量。外层函数执行完、调用栈都弹出了，这些变量还不回收，因为内部函数还引用着它们。

**三个用处**：

- **数据私有化**：只暴露方法，变量外面改不到，模块封装和状态机都靠它。
- **记住状态**：防抖节流里的 timer、状态标记，靠闭包存着。
- **循环里锁住当前值**：下面那道题就是。

**代价**：被引用的变量永远不会回收。闭包捏着大数组或 DOM 节点，内存会一直涨；用完把引用置 `null`，整个闭包才释放。

**经典题**：

```js
for (var i = 1; i <= 5; i++) {
  setTimeout(() => console.log(i), i * 1000)
}
// 输出五个 6
```

原因：`var` 没有块级作用域，五个回调共享同一个 `i`，循环早就跑完，`i` 定在 6。

三种解法：

```js
// 1. IIFE，把当时的值传进去
for (var i = 1; i <= 5; i++) {
  (function (j) { setTimeout(() => console.log(j), j * 1000) })(i)
}

// 2. setTimeout 第三个参数，作为回调的入参
for (var i = 1; i <= 5; i++) {
  setTimeout((j) => console.log(j), i * 1000, i)
}

// 3. 直接换 let，每轮新建绑定
for (let i = 1; i <= 5; i++) {
  setTimeout(() => console.log(i), i * 1000)
}
```

## 浅拷贝

`Object.assign`、展开运算符、`slice`、`concat`——都只拷第一层。第一层的基本类型值独立了，第一层的引用类型还共享同一个内层对象，改一处两处都变。

## 深拷贝

**一、`JSON.parse(JSON.stringify(x))`**

够用，但边界很硬：

- 丢 `undefined`、`symbol`；
- 函数在对象里被直接丢弃，在数组里变成 `null`；
- `Date` 变字符串，`Map`、`Set`、`RegExp` 全丢；
- 循环引用直接报错。

**二、`structuredClone(x)`**

现代首选，浏览器原生 API，结构化克隆算法：

- 支持 `Date`、`RegExp`、`Map`、`Set`、`ArrayBuffer`、`Blob`、`File`，**支持循环引用**；
- 不支持函数（抛 `DataCloneError`）、`Symbol`、`WeakMap`/`WeakSet`；
- 不复制原型链和 getter/setter，只落值。

**三、手写，讲思路就行**

四个要点：

1. 递归，遇到对象继续拆；
2. 用 **`WeakMap` 记录已拷贝的对象**，解循环引用；用 WeakMap 不用 Map，是让键能被自动回收，不然大对象拷完内存还赖着；
3. 先判 `null`，再判 `typeof` —— `typeof null` 是 `'object'`，漏了这步 null 会被拷成 `{}`；
4. 只遍历**自有可枚举**属性（`Object.keys`），不能用 `for...in`，否则原型链上的属性也会被拷进来；`Date`、`RegExp`、`Map`、`Set` 要单独分支处理，否则拷出来是个空对象。

## 原型链

两个东西别混：

- **`prototype`**：函数才有的属性，指向一个对象，这个对象上的 `constructor` 又指回函数本身。
- **`__proto__`**：每个对象都有，指向上层原型。例外是 `Object.create(null)`，它连原型都没有。

**属性查找**：先从自身找，找不到沿 `__proto__` 往上，一直到 `Object.prototype`，再往上就是 `null`，还是没有就返回 `undefined`。

`hasOwnProperty` 判的是“属性在不在自己身上”；现在有更干净的写法 `Object.hasOwn(obj, key)`。

三个细节：

- 箭头函数没有 `prototype`，因为它不能 `new`。
- `Function.prototype.bind` 造出来的函数也没有 `prototype`。
- **别用 `constructor` 判断类型**：它在原型上，原型链一被改就错，`Object.create(null)` 出来的对象更是直接没有。

## new 做了什么

三步，能顺着说就不算背：

1. 新建一个对象，把它的 `__proto__` 指向构造函数的 `prototype`；
2. 以这个对象作为 `this`，执行构造函数；
3. 看构造函数返回了什么——返回**对象或函数**，就用它；返回基本类型或什么都没返回，就用第 1 步那个对象。

## call / apply / bind

- 三个都能改 `this`，第一个参数就是新的 this。
- 第一个参数传 `null`/`undefined`/不传，非严格模式下指向全局对象，严格模式下就是 `undefined`。
- 传参方式：`call` 是参数列表，`apply` 是数组；`bind` 也是参数列表，但可以分批传。
- 执行时机：`call`/`apply` **立即执行**，`bind` **返回一个新函数**。
- `bind` 只认第一次，再 `bind` 无效；`bind` 出来的函数也没有 `prototype`。

## 变量提升

- **函数声明**：整个函数被提到作用域顶部，声明前就能调用。
- **`var`**：只提声明，值是 `undefined`。
- **`let` / `const`**：也提升，但处在暂时性死区（TDZ），声明前访问直接报错——不是“没提升”，是“暂时不能访问”。
- 全局作用域下的 `var` 会挂到 `window` 上，`let`/`const` 不会。
- `const` 只是不能重新赋值，对象内容照样能改。

同名时函数声明优先：`function f(){}` 和 `var f` 并存，函数声明先占位，之后的 `var f = ...` 赋值才会覆盖它。

经典题：

```js
var name = 'World!'
;(function () {
  if (typeof name === 'undefined') {
    var name = 'Jack'
    console.log('Goodbye ' + name)   // 走这里
  } else {
    console.log('Hello ' + name)
  }
})()
```

输出 `Goodbye Jack`。原因是 `if` 里的 `var name` 被提到了函数作用域顶部，所以 `typeof name` 是 `'undefined'`，进了 if 分支。

## 变量查找

当前作用域找不到，就沿作用域链往外层找，直到全局；全局也没有就抛 `ReferenceError`（注意这和“对象属性找不到返回 `undefined`”是两回事）。

## 继承

| 方式 | 做法 | 主要问题 |
|---|---|---|
| 原型链继承 | `Child.prototype = new Parent()` | 引用属性被所有实例共享；不能给父类传参 |
| 构造函数继承 | 子类里 `Parent.call(this)` | 拿不到父类原型上的方法；方法没法复用 |
| 组合继承 | 两个都用 | 父构造函数被调用两次，实例上多一份冗余属性 |
| 原型式继承 | `Object.create(parent)` | 引用属性还是共享 |
| 寄生式继承 | 原型式 + 给新对象加方法 | 同原型式 |
| 寄生组合式 | `call` + `Object.create(Parent.prototype)` | 没有明显缺陷，是标准做法 |

一句话收尾：**`class` 就是寄生组合式的语法糖**。被追问时，值得展开的只有“组合继承为什么调两次父构造函数”——一次在 `call` 里，一次在 `new Parent()` 里。

class 比函数写法多出来的能力：类体默认严格模式；`#field` 是**真私有**（外部访问直接报错，不是靠约定）；支持 `static {}` 静态初始化块；`new.target` 能判断是否被 `new` 调用；不用 `new` 直接调用会抛 `TypeError`。

## ES Module 与 CommonJS

| | ESM | CJS |
|---|---|---|
| 加载时机 | 编译时静态分析 | 运行时 `require` |
| 导出 | **值引用（活绑定）**，导出方改了，导入方跟着变 | **值拷贝**，导出后改原变量影响不到已导入的 |
| 顶层 `this` | `undefined` | `module.exports` |
| 能否 tree-shaking | 能 | 不能 |
| 典型场景 | 浏览器、打包器 | Node 传统模块、动态加载 |

- ESM 的导出是**只读绑定**，不能直接改 `import` 进来的变量。
- 互操作：ESM 里 `import` 一个 CJS 包，拿到的是 `module.exports`（一般挂在 `default` 上）；CJS 里想加载 ESM 只能用动态 `import()`。
- ESM 能被 tree-shaking，前提就是它是静态结构；CJS 的 `require` 是运行时求值，静态分析不出依赖。

## Proxy

一句话：**拦截对对象的基本操作**，返回一个新的代理对象。

- 支持 13 种拦截（`get`、`set`、`has`、`deleteProperty`、`apply`、`construct` 等），比 `Object.defineProperty` 细得多。
- **操作原对象不会触发拦截**，必须走 `proxy.xxx`。
- **不用递归**：一次性代理整个对象，嵌套对象等访问到再代理（惰性），Vue3 的响应式就是这么做的。
- `Object.defineProperty` 只能劫持**已存在**的属性，新增和删除属都要手动处理，数组下标也麻烦——这就是 Vue2 换 Vue3 的根本原因。
- trap 里用 `Reflect.get` / `Reflect.set` 保持默认行为，注意 `receiver` 别丢。

## 节流与防抖

两个都是“限制触发频率”，区别只在**什么时候真的执行**：

- **防抖**：停下来才执行，中间每次都重置计时器。搜索框输入、窗口 resize。
- **节流**：固定频率执行，中间触发直接丢。滚动加载、拖拽。

一句话记：**防抖是“最后那次”，节流是“每隔多久一次”**。

## 内存泄漏

垃圾回收判断不出“还在被引用”的对象，就不会回收。常见的五处：

- 意外的全局变量；
- 闭包长期持有大对象；
- 定时器、延时器没清；
- 事件监听没解绑；
- 已经移除的 DOM 还被 JS 变量引用着。

## 垃圾回收

- **引用计数已被淘汰**，它解不了循环引用。
- 现在是**标记清除**：从根出发标记所有可达对象，没被标记的清掉。
- V8 再按**分代**做：新生代对象小、死得快，用 Scavenge 复制存活对象；活过几轮挪到老生代，用标记清除/标记整理。
- 被问到，答“标记清除 + 分代”两个词就够。

## 数字精度

`0.1 + 0.2 !== 0.3`：JS 用 IEEE 754 双精度（64 位），0.1 在二进制里是无限循环小数，存不下只能截断，两个截断值一加，误差就露出来了。

`console.log(0.1)` 看着正常，是因为打印时输出的是“最短能还原这个数的十进制写法”，不是这个数真的精确。

金额别用浮点：按分存整数，或者用专门的精确小数库。
