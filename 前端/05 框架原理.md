# 05 框架原理

## 数据驱动（MVVM）

- Vue 和 React **都不是 MVVM 框架**，只是借鉴了这个思路。
- MVVM：View 是视图，Model 是数据，中间加一层 ViewModel 负责“数据变了视图跟着变”。双向绑定只是手段，不是目的。
- 和 MVC 的区别：MVC 里 Controller 要手动指挥两边；MVVM 是把这层同步自动化了。
- 精髓不在双向绑定，在于**把状态和用户行为从视图里抽出来**，视图只负责画。

## 虚拟 DOM

就是一个用 JS 对象描述 UI 的结构：`{ tag, props, children }`。

三个作用：

- **声明式**：你只描述“应该长什么样”，不写“怎么改”。
- **diff 的比较基准**：有它可以先算清楚差异，再一次性落到真实 DOM。
- **跨端**：同一棵 vdom 能渲染到浏览器、SSR、小程序、Native。

要说清一个常见误会：**虚拟 DOM 不是比真实 DOM 快**。手工写的最优 DOM 操作一定比 vdom 快；它的价值是**保证下限**（人写得差也不会差到哪去）和**声明式**的写法。

“JS 引擎和 DOM 引擎两个线程来回切”是早期说法，现在两者在同一渲染线程，开销来自绑定层和布局重算。

## diff 在做什么

一句话：新老两棵树，**只做同层比较**，产出一串“最小操作”，再一次性打到真实 DOM 上。

1. **只比同一层**，不跨层级。跨层比较是指数级复杂度，同层比就是 O(n)。
2. **类型变了**（`div` 变 `span`）：整棵子树替换，不再往下比。
3. **类型相同**：先更新属性，再递归比 children。
4. 文本节点：直接改文本。

## 列表是怎么比的

难点在于：数组里的元素没有身份，得靠 **key** 认人。

**老实现（snabbdom / Vue2）是双端比较**：

- 四个指针：老树头部、老树尾部、新树头部、新树尾部。
- 依次试四种组合：头对头、尾对尾、头对尾、尾对头。命中就复用，指针向内收。
- 四种都没命中：拿新节点的 key 去老节点的 map 里找——找到就**移动**，找不到就**新建**。
- 两个指针交叉以后收尾：老的还有剩就**删**，新的还有剩就**插**。

双端比较的好处是：在头部或尾部增删元素这种最常见的情况，一次比较就命中，几乎不需要移动。

**Vue3 换了思路**：先把新旧序列首尾相同的部分掐掉，剩下的乱序段用**最长递增子序列**算出“哪些节点可以原地不动”，只移动其余节点——移动次数最少。

**React 是单端遍历**：从左往右比，用一个 `lastPlacedIndex` 记录“最后一个没动的老节点位置”，新节点的位置比它小就说明要往右挪；真正搬家靠 `insertBefore`。

不管是哪一种，**diff 的产出都不是一棵新树**，而是“改哪个属性、插哪个、删哪个、谁要移动”。

## 为什么要 key

- 不写 key：按位置复用，列表一旦插入或删除，后面全体错位，组件状态会串到别的行（输入框内容跑到别的行上）。
- 用 `index` 当 key 等于没写，删除时一样错位。
- 必须是**唯一且稳定**的 ID。

## Vue 与 React 的取向差别

- **描述 UI 的方式**：模板（编译器能看懂结构）vs JSX（就是 JS 表达式）。这决定了后面的优化路线完全不同。
- **数据变了的通知方式**：Vue 用 Proxy 自动追踪，改了就精确更新；React 靠 `setState` 手动触发，然后整组件重渲染。
- **更新粒度**：Vue 精确到组件甚至具体属性；React 默认组件级，要更细就上 `memo` / `useMemo`。
- **优化思路**：Vue 把活挪到**编译期**；React 把活留给**运行时**（memo、调度）。
