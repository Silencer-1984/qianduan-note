## 一、语言特性与解释器

**1. Python 是什么类型的语言？有哪些特点和优缺点？（华为 / 字节跳动 / 阿里巴巴）**
解释型、动态类型、强类型、面向对象的高级通用语言，同时支持函数式和过程式写法。优点：语法简洁、开发效率高、生态最全（数据/AI/Web/运维）、当胶水语言易与 C 扩展集成；缺点：GIL 限制多线程并行、裸循环性能差、动态类型让大型项目重构和静态检查更吃力、内存开销偏高。

**2. Python 是解释型语言还是编译型语言？Python 需要编译吗？（字节跳动 / 腾讯）**
通常归为解释型，但严格说会先编译成字节码再由虚拟机执行，只是这一步对用户透明、不产出独立可执行文件。所以「需要编译」——编译到 `.pyc` 字节码，但不编译到机器码；PyPy 带 JIT 才会在运行时生成本地代码。

**3. Python 代码的执行过程是怎样的？（华为 / 美团）**
源码 → 词法/语法分析生成 AST → 编译成字节码（缓存为 `__pycache__/*.pyc`）→ CPython 栈式虚拟机逐条执行指令 → 运行时靠对象模型和引用计数管理内存。导入模块时先查 `sys.modules`，命中就不重复执行顶层代码。

**4. Python 是强类型还是弱类型？怎么理解它的动态类型？（字节跳动 / 滴滴）**
强类型：`1 + "1"` 直接抛 `TypeError`，不做隐式转换；动态类型：类型绑定在**对象**上而不是变量上，变量只是指向对象的名字，可以随时重新绑定到任何类型，类型检查发生在运行时。

**5. Python 是如何实现动态类型的？（字节跳动 / 滴滴）**
每个对象头部都带 `ob_type` 类型指针（`PyObject`），变量只是命名空间字典里 name → 对象指针的映射；名字本身无类型，属性和方法的查找在运行时通过类型指针、`__dict__`、描述符完成。灵活的同时也意味着每次运算都要做类型分发，这是慢的根源之一。

**6. Python 和 Java 的主要区别是什么？（字节跳动 / 腾讯 / 美团）**
Java 静态类型、编译成 class 跑 JVM 并有 JIT；Python 动态类型、编译成 pyc 跑 CPython 栈机。并发上 Java 原生多线程并行，Python 受 GIL 约束；内存上 Java 纯追踪式 GC，Python 以引用计数为主加分代回收兜循环引用。Java 更适合大型长期维护的工程，Python 胜在开发效率和生态。

**7. Python 和 C++ 的区别是什么，各自适合什么场景？（字节跳动 / 百度 / 美团）**
Python 动态、自动内存管理、开发快、性能靠 C 扩展兜底；C++ 静态编译到机器码、RAII 管内存、零成本抽象、延迟和内存完全可控。Python 做脚本、数据、AI、Web 后端和胶水；C++ 做游戏引擎、高频交易、嵌入式、驱动等对性能有硬要求的系统。

**8. Python、Java、Go 三种语言有什么区别？（腾讯 / 美团 / 字节跳动）**
Python 动态解释 + GIL，开发效率优先；Java 静态类型 + JVM + JIT，工程规范和企业生态成熟；Go 静态编译成单二进制、原生 goroutine 与 channel、无 GIL 直接用多核、启动快、部署最简。选型看取舍：要生态和迭代速度选 Python，要大型团队协作选 Java，要高并发服务和运维简单选 Go。

**9. Python 和 Go 的区别，不要停留在语法层面。（字节跳动 / 腾讯）**
核心在运行时模型：CPython 有 GIL，多线程无法并行执行字节码，CPU 密集只能多进程；Go 的 GMP 调度器把 goroutine 映射到多核，天然并行，且自带 channel/select 的并发原语。内存上 Python 引用计数 + 分代 GC、对象头开销大，Go 有逃逸分析、栈上分配和并发三色标记。部署上 Go 是静态单文件，Python 要带解释器和虚拟环境。工程上 Go 编译期暴露类型问题，Python 靠类型注解 + mypy 补。

**10. Python 和 JavaScript 有什么区别？（京东 / 腾讯）**
都是动态脚本语言，但 Python 强类型、JS 弱类型（`1 + "1"` 得 `"11"`）；Python 用缩进分块，JS 用花括号；并发模型不同，JS 是单线程事件循环（Node 靠 libuv 线程池补 IO），Python 是多线程 + GIL，另有一套 asyncio；继承上 JS 是原型链，Python 是基于类的多继承。生态上 JS 主导前端/Node，Python 主导数据、AI 与后端脚本。

**11. Python 2 和 Python 3 有哪些区别？（美团 / 华为 / 京东）**
`print` 变函数；`/` 改真除法、`//` 才是整除；`str` 默认 Unicode 并与 `bytes` 严格分离；`range`、`map`、`dict.keys()` 等返回惰性迭代器/视图而非列表；异常语法 `except E as e`、`raise ... from`；新增 `async/await`、类型注解、`yield from`、`nonlocal`、字典保序、`match`。Python 2 已于 2020 年停止维护，新项目一律用 3。

**12. Python 为什么执行速度慢？怎么优化 Python 的性能？（华为 / 腾讯）**
慢在：字节码解释调度开销、一切皆对象带来的装箱与间接寻址、动态类型每次运算都要查类型、属性查找走字典、GIL 限制多核。优化顺序：先 `cProfile`/`line_profiler` 定位热点 → 换算法与数据结构 → 用内置函数和推导式（C 层实现）→ 局部变量替代全局查找 → 热点下沉到 C（NumPy / Cython / Numba / Rust 扩展）→ CPU 密集用多进程，IO 密集用 asyncio。3.11+ 的自适应专用解释器已有明显提速。

**13. Python 有 JIT 吗？理论上能不能做？**
CPython 官方没有传统 JIT，3.11 起是 specializing adaptive interpreter（按运行时类型特化指令，但不生成机器码），3.13 起提供实验性的 JIT 编译框架。完全能做——PyPy 的 tracing JIT、Numba 基于 LLVM 的数值 JIT 都是现成例子。难点是动态类型和庞大的 C API 让类型推断不稳定，优化收益容易被对象模型吃掉。

**14. Python 比 Java、Go 快吗？（腾讯）**
纯 CPU 密集的裸循环通常慢一个数量级；但 Web 服务多数时间耗在 IO 和数据库上，语言本身不是瓶颈，而 NumPy/Pandas 底层是 C，数值计算反而不慢。结论：别用裸 Python 循环做重计算，比较要在同等优化程度下才有意义。

**15. CPython 是什么？解释器还有哪些实现？**
CPython 是官方 C 语言实现，也是事实标准（平时说的 Python 就是它），C 扩展生态（CPython C API）绑定在它身上。其他实现：PyPy（带 JIT，纯 Python 代码常快数倍）、Jython（JVM）、IronPython（.NET）、MicroPython（嵌入式）、GraalPy（GraalVM）；3.13 起还有可选的无 GIL free-threaded 构建。

**16. 字节码是什么，.pyc 文件是怎么来的？**
字节码是给 CPython 虚拟机执行的中间指令，介于源码与机器码之间，可用 `dis.dis(f)` 查看。`import` 时解释器把源码编译后写入 `__pycache__/xxx.cpython-3xx.pyc`，内含魔数、源文件时间戳/哈希和 marshal 序列化的 code object；下次导入若源文件未变就直接加载，省掉解析和编译。

**17. Python 为什么用缩进表示代码块？缩进用空格还是 Tab？**
强制缩进是语法层设计，可读性优先，用缩进替代 `begin/end` 或花括号，让「看到的层级」和「执行的结构」一致。PEP 8 推荐 4 个空格、不用 Tab；Python 3 中混用空格与 Tab 会直接抛 `TabError`。

**18. Python 的命名空间和作用域是什么？LEGB 规则怎么理解？（华为 / 腾讯）**
命名空间是名字到对象的映射（模块、类、函数、实例都各有 `__dict__`），作用域决定名字可见范围。查找顺序 LEGB：Local（当前函数）→ Enclosing（闭包外层函数）→ Global（模块）→ Built-in（内置名）。注意「赋值即在本作用域创建局部名字」，只有读取才向外层逐层找。

**19. Python 的全局变量、局部变量怎么声明？global 和 nonlocal 有什么用？（华为 / 腾讯）**
函数内赋值默认就是局部变量，无需声明；要改模块级变量用 `global x`，要改闭包外层（非全局）变量用 `nonlocal x`。只读不赋值不需要任何声明；函数内既有赋值又有读取同名全局名，会触发 `UnboundLocalError`。

**20. Python 是否区分大小写？**
区分。`name`、`Name`、`NAME` 是三个不同标识符；关键字和内置单例也大小写敏感，必须写 `True` / `False` / `None`。

**21. Python 的虚拟环境有什么用，为什么要用？（百度 / 腾讯）**
为每个项目隔离出独立的 `site-packages` 和解释器软链，解决不同项目依赖同一包的不同版本、以及避免污染系统 Python 权限的问题，也让依赖可复现。常用 `python -m venv .venv` 配 `requirements.txt`，或 Poetry / uv / conda 做锁定与解析。

**22. Python 的模块导入机制是怎样的？__init__.py 的作用是什么？**
`import` 先查 `sys.modules` 缓存，未命中则按 `sys.path` 顺序由 finder 定位、loader 加载，创建 module 对象、执行顶层代码并缓存；同名模块只执行一次。包是带 `__path__` 的特殊模块，`__init__.py` 标记目录为包、执行包级初始化、可用 `__all__` 控制 `from pkg import *`；Python 3.3+ 起支持没有该文件的命名空间包。

**23. Python 模块重载怎么实现？**
用 `importlib.reload(mod)`，它会在**原 module 对象**上重新执行代码并覆盖同名属性。坑：已创建的旧类实例不会自动更新，依赖模块不会递归重载，循环引用时容易出现半新半旧状态。生产环境不要依赖重载，调试用或重启进程更干净。

**24. == 和 is 有什么区别？（字节跳动 / 阿里巴巴）**
`==` 调用 `__eq__` 比较**值**，`is` 比较**对象身份**（`id()` 是否相同，是不是同一个对象）。`None` / `True` / `False` 这类单例要用 `is None` 判断；小整数池和字符串驻留会让 `is` 碰巧为 True，但那是实现细节，绝不能拿来比较值。

**25. a, b = b, a 在 Python 里是怎么实现交换的？**
右侧 `b, a` 先求值并打包成元组，再从左到右解包赋值给左侧名字，所以不需要临时变量。字节码层面是 `BUILD_TUPLE` → `UNPACK_SEQUENCE` → `STORE_*`，右侧所有表达式在赋值前已全部求值完毕。

**26. Python 里哪些值会被判断为 False？（阿里巴巴）**
`False`、`None`、数值零（`0` / `0.0` / `0j` / `Decimal(0)`）、空序列与空容器（`''`、`[]`、`()`、`{}`、`set()`、`range(0)`、`b''`），以及 `__bool__` 返回 `False` 或 `__len__` 返回 0 的自定义对象。注意 `bool([]) is False`，但 `[] == False` 仍是 False。

## 二、数据类型与内置数据结构

**1. Python 有哪些基本数据类型？（华为 / 字节跳动 / 小米）**
数值（`int` / `float` / `complex` / `bool`）、序列（`str` / `list` / `tuple` / `range`）、映射（`dict`）、集合（`set` / `frozenset`）、二进制序列（`bytes` / `bytearray` / `memoryview`），再加 `NoneType`。按是否可变分：可变的是 `list` / `dict` / `set` / `bytearray`，其余大多不可变。

**2. Python 常用的数据结构有哪些？（蔚来 / 字节跳动 / 百度）**
内置四件套 list（动态数组）、tuple（不可变序列）、dict（哈希表）、set（哈希集合），另有 `collections` 里的 `deque`（双端队列）、`defaultdict`、`Counter`、`OrderedDict`、`namedtuple`，以及 `heapq`（小顶堆）、`array.array`、`bisect` 有序列表。复杂结构可基于类自己实现链表/树。

**3. 列表、元组、字典、集合各自的特点和区别是什么？（腾讯 / 携程 / 字节跳动）**
list 有序、可变、可重复，按下标访问；tuple 有序、不可变、可重复，可哈希（元素也可哈希时）；dict 是键值对映射，3.7+ 保持插入顺序，key 必须可哈希；set 无序、去重、元素必须可哈希，支持交并差。查找上 dict/set 平均 O(1)，list 按下标 O(1)、按值 O(n)。

**4. list 和 tuple 的区别是什么，什么时候用元组？（华为）**
核心是可变性：list 可增删改，tuple 创建后不能改，因而可哈希、能当 dict 的 key，且内存更紧凑、创建更快。用途上：tuple 表达「一条固定结构的记录」（坐标、数据库一行、函数多返回值、作为常量），list 表达「同类型的可变集合」。另外 tuple 没有 `append` 等方法，也不会被意外修改，适合做只读约定。

**5. list 和 set 有什么区别？（百度 / 快手）**
list 有序、允许重复、底层动态数组，按值查找 O(n)；set 无序、自动去重、底层哈希表，查找平均 O(1)。set 的元素必须可哈希，且不支持下标索引；需要去重或频繁做 `in` 判断、交并差运算时用 set，需要顺序和重复元素时用 list。

**6. Python 里哪些数据类型是有序的，哪些是无序的？（美团）**
有序（保持插入/定义顺序）：`str` / `list` / `tuple` / `range`，以及 3.7+ 的 `dict`；无序：`set` / `frozenset`（迭代顺序由哈希和表容量决定，不能依赖）。注意「有序」指可按下标或按插入顺序迭代，不等于「已排序」。

**7. 字典的底层是怎么实现的？（字节跳动 / 百度）**
CPython 3.6+ 用「紧凑哈希表」：一块连续的 entries 数组按插入顺序存放 `hash/key/value` 三元组，另一块稀疏的 indices 数组是哈希表，只存 entry 在 entries 中的下标。查找时 hash → indices 槽位 → entry 下标 → 再比对 key 是否相等。相比旧版每项都存完整 entry 的稀疏表，省内存约一半，且天然保序。

**8. 字典的哈希冲突是怎么处理的？**
开放寻址法（不是链地址法）。CPython 用扰动序列探测：`perturb = hash`，每次 `i = (i*5 + 1 + perturb) & mask; perturb >>= 5`，把初始线性探测打散成伪随机序列，兼顾缓存局部性和分布均匀性。删除时要用哑元标记，否则探测链会断。

**9. 字典的 key 有什么要求，为什么列表不能当 key？（快手 / 阿里巴巴）**
key 必须可哈希，即实现 `__hash__` 且生命周期内哈希值不变，通常还要求 `__eq__` 与哈希一致。list 可变，内容一变哈希就变，会导致表里再也找不到这个 key，所以直接被设为不可哈希（`unhashable type: 'list'`）；同理 dict、set 也不行，而 tuple / str / int / frozenset 可以。

**10. 字典的扩容过程是怎样的，时间复杂度是多少？**
填充率超过约 2/3 时触发 resize：分配更大的 indices 数组（容量取 2 的幂，约为已用槽的 3 倍），把旧 entries 的哈希重新散列写入新索引；entries 数组本身可以原地搬移，不必重算 key 的哈希。单次最坏 O(n)，但按插入序列**均摊 O(1)**；只扩不缩，删光元素也不会自动缩容。

**11. 字典删除一个元素，底层发生了什么？**
不真删槽位，而是把 indices 里该位置标记为 `DKIX_DUMMY`，entries 中对应 key/value 置空并维护一个可复用的 free list。必须用哑元是因为开放寻址下探测链靠「空槽」终止，直接置空会让后面的冲突元素全部查不到；后续插入可以复用 dummy 槽。

**12. 字典的查找时间复杂度是多少？**
平均 O(1)：一次哈希、若干次探测、一次 key 比较。最坏 O(n)（大量哈希冲突或恶意构造相同哈希，早期版本有过哈希碰撞 DoS，现在字符串哈希默认随机化加盐）；注意哈希冲突严重时会退化，但正常数据几乎不会。

**13. Python 3.7 之后字典有序是怎么保证的，OrderedDict 还有什么用？**
CPython 3.6 的紧凑哈希表把 entries 按插入顺序连续存放，迭代时只要顺序遍历 entries 即可，3.7 把这写进了语言规范。普通 dict 因此保序，但 `OrderedDict` 仍有独特能力：`move_to_end()` / `popitem(last=False)` 调整顺序、顺序敏感的相等比较（`OrderedDict` 之间比较会考虑顺序）、以及 `reversed()` 支持更早、实现 LRU 缓存更方便。

**14. list 的底层是怎么实现的，是链表还是数组？（滴滴）**
是动态数组（`PyListObject` 里一个 `PyObject**` 指针数组 + `ob_size` + 已分配容量 `allocated`），不是链表。所以它按下标随机访问 O(1)、缓存友好，但中间插入/删除要搬移元素 O(n)。容量不足时按约 1.125 倍的增长曲线重新分配，使 append 均摊 O(1)。

**15. list 的 append、insert、pop 时间复杂度分别是多少？（腾讯 / 阿里巴巴）**
`append` 均摊 O(1)（触发扩容时单次 O(n)）；`insert(i, x)` O(n)，因为 i 之后的元素都要右移，尾部插入近似 O(1)；`pop()` 不带参数删末尾 O(1)，`pop(0)` 或 `pop(i)` O(n)。按值 `remove(x)` 也是 O(n)（先查找再搬移）。

**16. 列表增删元素有哪些方法？（快手 / 网易）**
增：`append`（末尾单个）、`extend`（末尾批量展开）、`insert(i, x)`（指定位置）、`+` / `+=`（生成拼接结果或原地扩展）、切片赋值 `a[i:j] = seq`；删：`pop()` / `pop(i)`、`remove(x)`（删首个匹配值）、`del a[i]` / `del a[i:j]`、`clear()`、切片赋空。注意 `append([1,2])` 是加一个元素，`extend([1,2])` 是加两个。

**17. 怎么在遍历列表的同时删除元素？**
正序 `for x in a: a.remove(x)` 会因为删除后元素前移而跳项，是经典 bug。正确做法：倒序遍历 `for i in range(len(a)-1, -1, -1)`；或生成新列表 `a = [x for x in a if keep(x)]` / `list(filter(...))`；或用 `while` 手动控制索引，删除时索引不自增。最推荐过滤生成新列表，语义最清楚。

**18. 列表去重有哪些方法？怎么保持原顺序？（美团 / 网易）**
不要求顺序：`list(set(a))`（元素需可哈希，顺序会乱）；保序首选 `list(dict.fromkeys(a))`（3.7+ 字典保序，O(n) 且简洁）；老写法是 `seen = set(); [x for x in a if not (x in seen or seen.add(x))]`。元素不可哈希时只能逐项 `in` 比较或先转成可哈希的键。

**19. 列表反转有哪几种方法？**
`a.reverse()` 原地反转返回 None；`reversed(a)` 返回迭代器，需 `list(reversed(a))`；切片 `a[::-1]` 生成新列表；`a.sort(reverse=True)` 是排序不是反转，别混。原地用 `reverse()`，要保留原列表用切片或 `reversed()`。

**20. 切片是什么，[::-1] 和负索引是什么意思？切片会产生新对象吗？（华为 / 百度）**
切片语法 `a[start:stop:step]`，左闭右开，用 `slice` 对象传给 `__getitem__`；省略时 start/stop 按 step 正负取默认边界。`a[::-1]` 是 step = -1 也就是倒序复制；`a[-1]` 是最后一个元素，负索引等价于 `len(a) + i`。对 list / tuple / str 切片**产生新的浅拷贝对象**（只复制引用，嵌套对象仍共享）；`memoryview`、NumPy 数组的切片可能返回视图，不复制数据。

**21. 列表推导式是什么，和普通循环相比有什么优势？（携程 / 科大讯飞）**
`[f(x) for x in it if cond]` 用一个表达式完成映射 + 过滤，还有生成器表达式 `(...)`、字典/集合推导式。优势：语法紧凑、意图更接近声明式、在 C 层用专门的 `LIST_APPEND` 字节码构建列表，通常比 `for + append` 快。代价是嵌套两层以上可读性下降，有复杂逻辑或副作用时应写普通循环。

**22. 字符串有哪些常用处理方法？（快手）**
分割拼接 `split` / `rsplit` / `splitlines` / `join` / `partition`；清洗 `strip` / `lstrip` / `rstrip` / `replace` / `translate`；判断 `startswith` / `endswith` / `isdigit` / `isalpha`；查找 `find` / `index` / `count`；大小写 `lower` / `upper` / `title` / `casefold`；格式化 `f-string` / `format` / `%`；对齐填充 `ljust` / `zfill`。关键前提：str 不可变，所有方法都返回新字符串。

**23. 字符串反转有哪些写法？（腾讯 / 小米）**
最常用 `s[::-1]`；`''.join(reversed(s))` 更直白但慢一点；`''.join(s[i] for i in range(len(s)-1, -1, -1))` 属于手写；还可 `reduce(lambda a,b: b+a, s)`。工程上就用切片。注意处理 Unicode 组合字符时按码点反转可能拆坏字形，严谨场景需按 grapheme cluster 处理。

**24. 单引号、双引号、三引号的区别是什么？**
单双引号完全等价，只是方便在字符串里避免转义另一种引号。三引号 `'''`/`"""` 可跨行，保留换行和缩进，常用于文档字符串（`__doc__`）、多行模板和 SQL；单独一行的字符串字面量会做相邻拼接，三引号没有额外语义，不是「注释」。

**25. str 和 bytes 有什么区别？**
`str` 是 Unicode 码点序列（逻辑文本），`bytes` 是 0-255 的字节序列（二进制数据），Python 3 起两者严格分离，比较或拼接会报 TypeError。转换靠编解码：`s.encode('utf-8')` 得 bytes，`b.decode('utf-8')` 得 str，编码不一致就是乱码或 `UnicodeDecodeError`。IO 边界（文件、网络）拿到的是 bytes，用 `open(..., encoding=)` 让解释器自动解码。

**26. 怎么用 Python 实现队列、栈和链表？（华为 / 腾讯）**
栈：`list.append` + `list.pop`，简单但 `pop(0)` 当队列头是 O(n)；队列：优先 `collections.deque`（`append` / `popleft` 都是 O(1) 且线程安全），多生产者消费者用 `queue.Queue`（带锁和阻塞语义），进程间用 `multiprocessing.Queue`；链表：定义 `class Node: value, next` 加 `head` 指针实现插入删除，或直接用 `deque`。业务代码几乎不需要自己写链表。

**27. collections 里的 deque、defaultdict、Counter 分别用在什么场合？**
`deque` 是双端队列，两端 O(1)，适合队列、滑动窗口、BFS，还有 `maxlen` 做固定长度历史；`defaultdict` 给缺失 key 提供默认值工厂，省掉 `setdefault` / 判断，常用于分组 `defaultdict(list)`；`Counter` 统计频次，支持 `most_common()` 和加减交并运算，做词频、TopN 很顺手。

**28. set 的实际应用场景有哪些？**
去重（`set(seq)`）、快速存在性判断（`if x in seen`，O(1)）、集合运算（交集 `&` 找共同好友、差集 `-` 找新增/流失、并集 `|`）、以及把「按值查找」转成哈希查找以优化整体复杂度。注意元素必须可哈希，且结果无序，迭代顺序不可依赖。

**29. 元组为什么可以作为字典的 key？元组一定不可变吗？**
元组的「不可变」指其元素引用不可增删改，只要所有元素都可哈希，元组自身的哈希就能稳定，因此可当 key。但元组不一定整体不可变——`([1, 2],)` 里含 list，内容可变且不可哈希，这种元组做 key 会抛 `unhashable type`；判断标准是递归地所有元素可哈希。

**30. 整数在 Python 里占多少字节，有没有大小上限？**
CPython 的 `int` 是变长的大整数对象（`PyLongObject`），64 位下 `sys.getsizeof(0)` 为 28 字节，之后按每 30 bit 一个 digit（4 字节）增长，例如 2³⁰ 需要 32 字节。没有固定上限，`2**10000` 也能算，只受可用内存限制；这点和 C/Java 的定长 int 完全不同，也是 Python 整数运算偏慢的原因之一。

**31. /、//、% 在 Python 里分别做什么？5/2 输出多少？**
`/` 真除法总返回 float，`5/2` 是 `2.5`；`//` 地板除（向下取整，不是截断），`5//2 = 2`、`-5//2 = -3`；`%` 取模，结果符号与除数一致，`-5 % 2 = 1`。三者满足恒等式 `a == (a//b)*b + a%b`，`divmod(a, b)` 一次返回商和余数。

## 三、可变对象、拷贝与参数传递

**1. 什么是可变对象，什么是不可变对象？各举几个例子。（华为 / 美团 / 商汤）**
对象创建后能否在不改变身份（`id()`）的前提下修改内容：可变对象可以，如 `list` / `dict` / `set` / `bytearray` / 自定义类实例；不可变对象不行，如 `int` / `float` / `str` / `tuple` / `frozenset` / `bytes`。对不可变对象做「修改」实际是创建新对象再重新绑定名字。

**2. 字符串是可变对象还是不可变对象？（华为 / 哔哩哔哩）**
不可变。`s += 'x'` 并不是原地追加，而是生成新字符串再让 `s` 指向它（CPython 对无其他引用的局部字符串有个原地扩容优化，但语义上仍是不可变）。因此循环里反复拼接字符串是 O(n²)，应改用 `''.join(parts)` 或 `io.StringIO`。不可变带来可哈希、可安全共享、可做 dict key 等好处。

**3. 可变对象的原理是什么，不可变对象为什么线程安全？**
可变对象内部持有一组指向元素的引用，方法（`append` / `__setitem__`）原地改写这块存储，身份不变，所有引用它的名字都看到变化；不可变对象没有提供任何原地修改接口，状态从创建到销毁恒定。「线程安全」准确说是**不可变状态无需同步**：不存在中途被改写、不会有读写竞态，可以自由共享和缓存；但把不可变对象重新赋给一个共享名字，这个赋值动作本身仍需视情况加锁。

**4. 浅拷贝和深拷贝有什么区别？（华为 / 百度 / 美团）**
浅拷贝只复制最外层容器，内部元素仍共享同一批对象引用（`copy.copy`、`list(a)`、`a[:]`、`dict(a)` 都属此类）；深拷贝递归复制所有层级，生成一个完全独立的对象图（`copy.deepcopy`）。所以嵌套结构里改内层元素，浅拷贝会互相影响，深拷贝不会；`deepcopy` 还用 memo 字典记住已复制的对象，正确处理循环引用和共享引用。

**5. Python 怎么拷贝一个对象，copy 模块怎么用？（华为 / 美团 / 字节跳动）**
`copy.copy(x)` 浅拷贝、`copy.deepcopy(x)` 深拷贝；不可变对象（int/str/tuple of immutables）通常原样返回，因为改不了就没必要复制。自定义类可实现 `__copy__` / `__deepcopy__(memo)` 控制行为，比如把文件句柄、数据库连接、线程池这类不可复制资源保持共享或显式排除。

**6. 赋值、浅拷贝、深拷贝三者有什么区别？**
赋值 `b = a` 只是多一个名字指向同一对象，`b is a` 为 True；浅拷贝创建新外层容器，`b is a` 为 False 但 `b[0] is a[0]` 为 True；深拷贝连内层一起复制，内层 `is` 也为 False（不可变小对象因缓存例外）。判断标准就一句：复制到了第几层。

**7. 对列表切片后修改原列表，新变量会受影响吗？（华为 / 腾讯）**
`b = a[:]` 是浅拷贝，容器独立：之后 `a.append(x)` 或 `del a[0]` 不会影响 `b`。但如果元素是嵌套的可变对象（如 `a = [[1], [2]]`），改 `a[0][0]` 会影响 `b[0][0]`，因为两者共享内层列表。要彻底隔离用 `copy.deepcopy`。

**8. Python 是值传递还是引用传递？（阿里巴巴 / 华为 / 哔哩哔哩）**
都不是，更准确叫「传对象引用」（call by object reference / call by assignment）：形参被绑定到实参所指向的**同一个对象**，不复制对象，也不复制变量本身。于是函数内 `x = 新值` 只改局部绑定、不影响外部；而 `x.append(1)` 这类原地修改会通过共享对象影响到外部。

**9. 函数传参机制是怎样的，可变对象作参数会发生什么？（华为 / 阿里巴巴）**
调用时实参表达式先求值得到对象，再把对象引用按顺序/关键字绑定到形参，参数默认值在函数定义时求值并存在 `__defaults__` 里。传入 list/dict 这类可变对象时，函数内的原地修改（增删改元素）会反映到调用方；若不希望这样，应传副本（`list(a)`）或在函数内先拷贝，也别用可变对象当默认参数。

**10. 函数的默认参数为什么不能用可变对象？**
默认值在**函数定义时**求值一次，之后所有调用共享同一个对象。写 `def f(x, acc=[])` 时，每次 `acc.append(x)` 都在改同一个列表，结果跨调用累积，是经典 bug。正确写法是 `acc=None` 后在函数体内 `if acc is None: acc = []`；dict、set 同理。

**11. 函数参数有哪几种，怎么让参数数量不固定？**
按形态分位置参数、默认参数、可变位置参数 `*args`、仅关键字参数（`*` 之后）、可变关键字参数 `**kwargs`、以及用 `/` 分隔的仅位置参数（3.8+）。数量不固定就用 `*args` 收集多余位置参数为 tuple，`**kwargs` 收集多余关键字参数为 dict，两者可组合，顺序必须是 `def f(pos, /, pos_or_kw, *args, kw_only, **kwargs)`。

**12. *args 和 **kwargs 有什么区别？（华为 / 网易 / 快手）**
定义时 `*args` 把多余的位置实参收成元组，`**kwargs` 把多余的关键字实参收成字典；调用时 `f(*seq)` 展开序列为位置参数，`f(**mapping)` 展开字典为关键字参数。典型用途是装饰器透传参数、包装底层 API、子类构造调用 `super().__init__(*args, **kwargs)`。

**13. Python 中的 * 和 ** 除了收集参数还有什么用途？**
调用端解包 `f(*a)` / `f(**d)`；字面量里展开 `[*a, *b]`、`{*a, *b}`、`{**d1, **d2}`（3.5+）；赋值时扩展解包 `first, *rest = seq`；函数签名里裸 `*` 表示后面的参数只能按关键字传，`/` 前面的只能按位置传；类型注解里 `*Ts` / `**P` 用于可变参数的类型标注（PEP 646 / 612）。

**14. 小整数池和字符串驻留是什么？**
CPython 在启动时预创建并复用 `-5 ~ 256` 的小整数对象，避免高频小整数反复分配；字符串驻留（intern）把符合标识符规则的字符串、编译期常量等放入全局唯一表，同名字符串可能复用同一对象，可用 `sys.intern()` 手动驻留以加速比较。两者都是实现层面的优化，**绝不能用 `is` 来比较值**，跨解释器/版本行为不保证。

**15. id() 返回的是什么？**
返回对象在其生命周期内的唯一整数标识，CPython 中就是对象的内存地址。它只在对象存活期间唯一：对象被回收后地址会被复用，所以 `id(a) == id(b)` 但 a、b 不是同一生命周期的对象时没有意义；真正判断是不是同一个对象应该用 `is`。

## 四、函数、闭包与装饰器

**1. 装饰器是什么，有什么作用？（华为 / 百度 / 字节跳动）**
装饰器是一个「接收函数/类、返回新函数/类」的可调用对象，用 `@decorator` 语法在不改动原函数源码的前提下，给一批函数统一加上横切逻辑。作用是把日志、鉴权、缓存、重试、计时、事务、注册路由这类重复代码从业务里抽出来，保持单一职责。

**2. 装饰器的原理是什么？（华为 / 字节跳动 / 美团）**
`@dec` 本质就是语法糖，等价于 `func = dec(func)`，在模块导入/函数定义时立即执行。利用了「函数是一等对象」和闭包：外层函数接收原函数，内层 `wrapper(*args, **kwargs)` 保存对原函数的引用，在调用前后插入逻辑再 `return func(*args, **kwargs)`，最后返回 wrapper 顶替原名字。

**3. 装饰器的应用场景有哪些，项目里用在哪里？（携程 / 华为 / 蔚来）**
Web 框架路由注册与登录鉴权（`@app.route`、`@login_required`）、缓存与记忆化（`@lru_cache`）、耗时统计与链路追踪、异常重试与熔断、参数校验与序列化、权限与限流、事务/数据库会话管理、单元测试的 `@pytest.fixture`、以及 `staticmethod` / `property` / `dataclass` 这些内置装饰器。

**4. 手写一个最简单的装饰器。（腾讯 / 小米 / 快手）**
```python
from functools import wraps

def log(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print('call', func.__name__)
        return func(*args, **kwargs)
    return wrapper

@log
def add(a, b):
    return a + b
```
关键三点：内层用 `*args, **kwargs` 透传、把原函数返回值 `return` 出去、用 `@wraps` 保留元信息。

**5. 怎么写带参数的装饰器？（华为）**
比普通装饰器多套一层工厂：`def retry(times=3):` 返回真正的 `decorator(func)`，里面 `wrapper` 再包一层。所以 `@retry(times=3)` 先执行 `retry(3)` 得到装饰器，再应用到函数上，共三层嵌套。若想同时支持 `@dec` 和 `@dec(...)`，需判断第一个参数是不是可调用对象。

**6. 多个装饰器叠加时，执行顺序是怎样的？（华为 / 字节跳动）**
装饰（定义时）**自下而上**：离函数最近的先应用，`@A` 在 `@B` 上面时等价于 `f = A(B(f))`；调用时**自上而下**：先进入最外层 A 的 wrapper，再进入 B 的 wrapper，最后执行原函数，返回时逆序退出。可以类比洋葱模型，日志/计时类装饰器放最外层才能统计到内层耗时。

**7. 类装饰器怎么写？**
两种：一是用类来装饰函数，实现 `__init__(self, func)` 保存函数和 `__call__(self, *args, **kwargs)` 让实例可调用（能带状态，如计数器）；二是装饰器作用在类上，接收类并返回新类或原地给它加属性/方法（`dataclass`、`@register` 都是这类）。前者记得配合 `functools.update_wrapper(self, func)` 保留元信息。

**8. functools.wraps 的作用是什么，不加会怎样？**
它用 `update_wrapper` 把原函数的 `__name__` / `__doc__` / `__module__` / `__qualname__` / `__annotations__` 复制到 wrapper，并设置 `__wrapped__` 指向原函数。不加的话所有被装饰函数都叫 `wrapper`、文档丢失，`inspect.signature` 拿不到真实签名，pytest、FastAPI、Flask 这类靠函数元信息做注册和依赖注入的框架会直接出错。

**9. 怎么写一个统计函数耗时的装饰器？（腾讯 / 蔚来）**
`wrapper` 里 `t0 = time.perf_counter()`，用 `try/finally` 包裹 `func(*args, **kwargs)`，在 `finally` 里 `logger.info('%s took %.3fs', func.__name__, time.perf_counter() - t0)`。用 `finally` 保证抛异常也能记录；计时用 `perf_counter`（单调高精度），不要用 `time.time`；记得 `@wraps` 和把结果 return 出去。

**10. 怎么写一个异常自动重试的装饰器？（腾讯）**
带参数的装饰器里 `for i in range(times)` 循环 `try: return func(*args, **kwargs) except exceptions as e:`，未到次数就 `time.sleep(backoff * 2**i)`（指数退避）并记日志，最后一次仍失败就 `raise`。要点：只捕获可重试的异常（网络超时、连接错），别吞掉业务异常；可加随机抖动避免惊群；重试要保证被调函数是幂等的。

**11. 装饰器和闭包是什么关系？（京东）**
装饰器是闭包最典型的应用：外层装饰器函数的作用域里保存了 `func`（以及 `times`、`backoff` 这类参数），内层 wrapper 通过闭包 cell 引用它们，外层早已返回但变量依然存活。可以说「闭包是机制，装饰器是利用这个机制的一种设计模式」；反过来闭包不只是装饰器，还能做回调工厂、延迟计算、状态保持。

**12. Python 的闭包是什么，有什么用？（华为 / 字节跳动 / 美团）**
闭包是「内部函数 + 它引用的外层自由变量」的组合，外层函数返回后这些变量仍以 cell 对象形式存活（存在 `__closure__` 里）。用途：不使用全局变量就保存状态（计数器）、生成一族行为相似的函数（工厂）、实现装饰器、回调携带上下文。注意它捕获的是**变量本身**而不是当时的值。

**13. 闭包里修改外层变量需要注意什么？**
在函数里给名字赋值会被判定为局部变量，于是读外层同名变量时抛 `UnboundLocalError`。要真正修改外层变量需 `nonlocal x`（修改全局变量用 `global`）；如果变量是可变对象，用 `x.append(...)` 这类原地操作不算重新绑定，无需声明。Python 2 没有 `nonlocal`，只能借可变容器绕。

**14. lambda 表达式是什么，常用在哪些场景？（华为 / 快手 / 百度）**
`lambda args: expr` 创建匿名函数，函数体只能是单个表达式、不能有语句，返回该表达式的值。常用于 `sorted(key=lambda x: x[1])`、`map/filter` 的短回调、GUI/回调注册、`defaultdict(lambda: 0)`。复杂逻辑应写 `def`，可读性更好；lambda 同样支持默认参数和闭包。

**15. lambda 在循环里的延迟绑定问题是什么？**
闭包捕获的是变量而非值，循环里创建的 lambda 都引用同一个循环变量，等调用时循环早已结束，取到的是最后一次的值（如 `fs = [lambda: i for i in range(3)]` 全部返回 2）。解决办法：用默认参数在定义时固化 `lambda i=i: i`，或 `functools.partial`，或用工厂函数 `def make(i): return lambda: i`。

**16. map、filter、reduce 分别做什么？**
`map(f, it)` 对每个元素做映射，返回惰性迭代器；`filter(f, it)` 保留使 `f` 为真的元素，同样惰性；`reduce(f, it, init)`（在 `functools`，Python 3 已移出内置）把二元函数累积应用到序列上，得到单个值，如求和求积。多数场景列表推导/生成器表达式更 Pythonic，`sum` / `max` / `any` 等内置函数比手写 reduce 更清晰。

**17. 什么是高阶函数？函数在 Python 里为什么是一等公民？**
高阶函数是接收函数作参数或返回函数的函数，如 `map` / `sorted(key=)` / 装饰器 / `functools.partial`。一等公民指函数和其他对象地位相同：可赋值给变量、存进容器、作为参数传递、作为返回值、运行时动态创建（都有 `function` 类型和 `__call__`）。这源于「一切皆对象」，函数也是 `PyFunctionObject` 实例。

**18. 上下文管理器是什么？with 语句的原理是什么，怎么自己实现一个？（华为 / 小米 / 百度）**
上下文管理器把「获取资源 → 使用 → 必定释放」固化成一个协议。`with expr as x:` 先调用 `expr.__enter__()`，其返回值绑到 x；无论正常结束还是抛异常，退出时都调用 `__exit__(exc_type, exc, tb)` 做清理，返回 True 可抑制异常。两种实现方式：定义类实现这两个方法；或用 `contextlib.contextmanager` + 生成器，`yield` 之前是 enter、之后（放在 `finally` 里）是 exit，更简洁。文件、锁、数据库事务、`pytest.raises` 都基于此。

**19. @classmethod、@staticmethod、@property 分别是什么？（华为 / 快手）**
`@classmethod` 首参自动传类 `cls`，能访问类属性、被子类继承时绑定到子类，常作工厂方法（`from_dict`）；`@staticmethod` 不自动传任何参数，只是把普通函数放进类的命名空间，便于组织；`@property` 把方法变成数据描述符，可像属性一样读取，并可用 `@x.setter` / `@x.deleter` 加校验和惰性计算，实现「接口不变、内部改实现」。

**20. Python 支持函数重载吗？重载体现在哪里？（华为 / 理想）**
不支持 C++/Java 那种按参数类型和个数区分的同名重载——同名后定义会直接覆盖前一个。替代方案：默认参数 + `*args/**kwargs` 自己做类型分派、`functools.singledispatch` 按第一个参数的类型注册实现、`typing.overload` 只是给类型检查器看的声明。真正的「重载」体现在运算符和内置协议上（`__add__` / `__len__` / `__getitem__`），以及子类对父类方法的重写。

**21. 偏函数 functools.partial 有什么用？**
把函数的部分参数或关键字预先绑定，生成一个签名更短的新可调用对象，`partial(f, a, kw=v)(b)` 等价于 `f(a, b, kw=v)`。常用于把带多参的函数适配成回调接口、给线程池/`map` 传固定配置、固化 lambda 循环里的变量避免延迟绑定；它保留 `__name__` 丢失但可设置，比 lambda 更易被 pickle。

**22. 递归的深度限制是多少，怎么修改？**
默认 `sys.getrecursionlimit()` 通常是 1000，防止无限递归把 C 栈打爆，超了抛 `RecursionError`。可用 `sys.setrecursionlimit(n)` 调整，但调太大可能直接让解释器段错误崩溃，不是正当解法；正确做法是改写成迭代、用显式栈、加记忆化，或确认是否存在未收敛的递归条件。

## 五、迭代器与生成器

**1. 迭代器和生成器有什么区别？（中兴 / 科大讯飞 / 京东）**
迭代器是**协议**：实现 `__iter__`（返回自身）和 `__next__`（返回下一项或抛 `StopIteration`）；生成器是**语法机制**：含 `yield` 的函数或生成器表达式，自动生成一个实现了迭代器协议的对象，还额外有 `send` / `throw` / `close`。所以生成器一定是迭代器，迭代器不一定是生成器；生成器能保存执行栈帧暂停/恢复，代码更简洁，而自定义迭代器要自己维护状态。

**2. 可迭代对象和迭代器是什么关系？（百度）**
可迭代对象实现 `__iter__`（返回迭代器）或 `__getitem__` 序列协议，能被 `for` 和 `iter()` 消费；迭代器一定能被迭代，且自己记住进度。`for x in obj` 实际是 `it = iter(obj)` 然后反复 `next(it)` 直到 `StopIteration`。list / str / dict 是可迭代对象但不是迭代器（每次 `iter()` 都给新的），`iter(list)`、文件对象、生成器则是迭代器（一次性）。

**3. 怎么自定义一个迭代器？__iter__ 和 __next__ 分别做什么？**
在类里维护游标，`__iter__` 返回 `self`（让对象同时满足可迭代协议），`__next__` 计算并返回一个元素、越界时 `raise StopIteration`。也可以让 `__iter__` 用 `yield` 写成生成器，代码更短。注意不要在 `__next__` 里返回 `None` 表示结束，for 循环只认 `StopIteration`。

**4. 生成器是什么，怎么创建？（华为 / 小米 / 百度）**
生成器是一种惰性产出值的迭代器，调用时不执行函数体，而是返回一个保存了栈帧的生成器对象，每次 `next()` 执行到下一个 `yield` 就挂起。两种创建方式：函数体里出现 `yield`（或 `yield from`）的生成器函数；生成器表达式 `(x*x for x in it)`。判断可用 `inspect.isgenerator()`。

**5. yield 的作用是什么？它和 return 有什么区别？（小鹏 / 百度 / 腾讯）**
`yield` 产出一个值给调用方并**暂停**函数、完整保留局部变量和执行位置，下次 `next()` 从断点继续；`return` 直接结束函数并销毁栈帧。含 `yield` 的函数整体变成生成器函数，调用它不会立即执行任何一行代码；生成器里的 `return v` 也不产出元素，而是把 v 放到 `StopIteration.value` 里。

**6. 生成器函数的返回值是什么？**
调用生成器函数返回的是**生成器对象**（`types.GeneratorType`），不是函数体内 return 的值。函数体内 `return value` 会终止迭代并让 `StopIteration.value == value`，通常配合 `yield from` 接收子生成器的返回值；直接 for 循环时这个值会被吞掉，需要手动捕获 `StopIteration` 才能拿到。

**7. yield from 是做什么的？**
把迭代委托给子迭代器：`yield from it` 等价于把 it 的每个值依次 yield 出去，但更完整——自动透传 `send()` / `throw()` / `close()` 给子生成器，并把子生成器 `return` 的值作为整个表达式的结果返回。主要用于生成器嵌套、递归遍历和基于生成器的协程；`asyncio` 早期就是用 `yield from` 驱动协程的。

**8. 生成器表达式和列表推导式有什么区别？**
`(f(x) for x in it)` 返回生成器，惰性计算、逐个产出、只占 O(1) 内存、只能消费一次；`[f(x) for x in it]` 立即构建完整列表、占 O(n) 内存、可重复遍历和索引。数据量大、只需单次流式处理（如 `sum(...)`、逐行处理文件）用生成器表达式；需要复用、切片、多次遍历或要 `len()` 时用列表推导。

**9. 生成器的 send、throw、close 方法有什么用？**
`send(v)` 把 v 作为当前暂停的 `yield` 表达式的结果送进去并恢复执行，实现调用方与生成器的双向通信（首次必须 `send(None)` 或 `next()` 启动）；`throw(exc)` 在暂停处抛出指定异常，让生成器有机会在 `except` 里处理；`close()` 在暂停处抛 `GeneratorExit`，触发 `finally` 释放资源。三者是生成器能做协程式协作的基础。

**10. 生成器为什么省内存，适合处理什么场景？**
因为它一次只保存一个栈帧和当前元素，不把全部结果物化到内存，复杂度从 O(n) 降到 O(1)；而且可以边生产边消费，首元素延迟低。适合大文件逐行读取、数据库游标流式拉取、无限序列（斐波那契、日志流）、数据管道链式处理、以及内存受限下的批量任务。

**11. 迭代器耗尽之后再次遍历会怎样？**
迭代器状态是单向的，耗尽后再 `next()` 只会继续抛 `StopIteration`，用 for 遍历就是「什么都不做、静默结束」，不会报错也不会重置。生成器、文件对象、`map` / `zip` 结果都是这样。要重新遍历必须重新创建：`iter(container)` 拿新的迭代器，或重新调用生成器函数；需要多次遍历就先 `list(it)` 固化（代价是内存）。

**12. 哪些内置数据类型是可迭代的？**
序列类 `str` / `list` / `tuple` / `range` / `bytes` / `bytearray` / `memoryview`，映射 `dict`（迭代 key，另有 `.items()` / `.values()` 视图），集合 `set` / `frozenset`，以及文件对象、`enumerate` / `zip` / `map` / `filter` 返回的迭代器、`re.finditer` 等。判断标准看能否被 `iter()` 接受，或用 `isinstance(x, collections.abc.Iterable)`。

## 六、面向对象

**1. Python 的类有哪些特点？怎么理解 Python 的面向对象？（华为 / 腾讯）**
一切皆对象，类本身也是 `type` 的实例；支持多继承、鸭子类型、动态添加属性和方法、丰富的魔术方法协议、基于描述符的属性访问控制。Python 的 OO 更偏「协议 + 约定」而非强制封装：没有真正的私有成员，多态靠鸭子类型而不要求显式继承同一基类，所以组合往往比深层继承更受欢迎。

**2. 封装、继承、多态在 Python 里分别怎么体现？（华为 / 快手 / 字节跳动）**
封装：用 `_name` 约定、`__name` 名称改写、`@property` 和描述符控制访问，把实现细节藏起来；继承：`class B(A)` 支持多继承，MRO 用 C3 线性化，`super()` 协作调用；多态：鸭子类型——只要对象实现了对应方法就能用，不要求共同父类，`len(x)` 对 list/str/dict 都生效，另可用 `abc` 或 `Protocol` 做显式接口约束。

**3. Python 的私有变量怎么实现？单下划线和双下划线有什么区别？**
没有真正的私有，都是约定。`_name` 是「内部使用」的君子协定，`from m import *` 不会导入它，但外部仍可直接访问；`__name` 会触发名称改写（name mangling），编译期变成 `_ClassName__name`，主要目的是**避免子类意外覆盖同名属性**，而不是防泄密，知道规则照样能访问。`__x__` 这种前后双下划线是魔术方法，别用于自己的属性。

**4. 类变量和实例变量有什么区别？**
类变量定义在类体内、存在 `Class.__dict__`，被所有实例共享；实例变量在 `__init__` 里 `self.x = ...`、存在各自的 `__dict__`。读取时先找实例再找类，所以 `self.x` 可能读到类变量；但 `self.x = v` 永远是给实例**新建/覆盖**一个属性，不会改类变量。经典坑：把可变类变量当实例默认值用（如 `class A: items = []`），所有实例会共享同一个列表。

**5. 类方法、实例方法、静态方法的区别和使用场景是什么？**
实例方法首参 `self`，能访问实例和类状态，最常用；类方法 `@classmethod` 首参 `cls`，可访问类属性且对子类自动绑定子类，常用于工厂方法、替代构造器、类级计数器；静态方法 `@staticmethod` 不自动传参，等价于放在类命名空间里的普通函数，适合与类相关但不依赖实例/类状态的工具函数。三者本质都是描述符，差别在绑定行为。

**6. __init__ 和 __new__ 有什么区别，执行顺序是怎样的？（阿里巴巴 / 腾讯 / 华为）**
`__new__` 是静态方法，首参 `cls`，负责**创建**并返回实例（通常 `super().__new__(cls)`）；`__init__` 首参 `self`，负责**初始化**已创建的实例，不能返回值。顺序由元类的 `type.__call__` 串起来：`__new__` → 若返回的是 cls 的实例则调用 `__init__` → 返回对象。若 `__new__` 返回的不是本类实例，`__init__` 不会被调用；实现单例、继承不可变类型（int/str/tuple）、元类定制时要改 `__new__`。

**7. Python 的构造函数和析构函数是什么？（字节跳动 / 华为）**
构造通常指 `__new__`（真正创建）和 `__init__`（初始化）两步，日常说「构造函数」多指 `__init__`；析构是 `__del__`。但 `__del__` 的调用时机不可靠——引用计数归零时一般在 CPython 立刻触发，循环引用对象要等 GC，解释器退出时也不保证执行，且异常会被忽略。**不要用它释放关键资源**，应改用 `with` 上下文管理器或 `weakref.finalize`。

**8. 一个对象的创建过程是怎样的？**
调用类（等价于调用元类的 `__call__`）→ `type.__call__` 先调 `cls.__new__(cls, *args)` 分配并得到实例 → 若结果是 cls 的实例，再调 `instance.__init__(*args)` 初始化 → 返回实例。中间还涉及 `metaclass`、`__init_subclass__`（类创建时）、描述符绑定（方法访问时）。理解这条链路才能解释 `__new__` 返回其他类型时为何 `__init__` 不执行。

**9. self 是什么？**
`self` 只是约定俗成的形参名，表示调用该方法的**实例本身**；解释器在绑定方法时通过描述符自动把实例作为第一个参数传进去，所以定义要写 `self`、调用 `obj.m()` 不用传。换成 `this` 或其他名字语法上完全合法，但会破坏团队约定和静态工具；类方法对应位置是 `cls`，同理也是约定名。

**10. Python 支持多继承吗？MRO 的顺序是怎样的？（华为）**
支持。MRO（方法解析顺序）用 **C3 线性化**：保证子类优先于父类、多个基类保持声明时的相对顺序、且满足单调性（任何类的 MRO 中父类顺序与其自身 MRO 一致），冲突时直接抛 `TypeError: Cannot create a consistent MRO`。可用 `Class.__mro__` 或 `Class.mro()` 查看；实际查找属性时按这个元组从左到右找。

**11. 菱形继承是怎么解决的？**
菱形（D→B、C，B/C→A）在旧的深度优先 MRO 下，D 调用方法会先走 B→A 再走 C→A，导致顶层 A 被重复访问、C 的重写被跳过。C3 把 D 的 MRO 排成 `D, B, C, A, object`，每个类只出现一次、顺序合理；配合 `super()` 的「沿 MRO 找下一个」语义，形成协作式多继承链，每个类的方法只执行一次（前提是链上每个方法都调用 `super()`）。典型应用是 mixin。

**12. super() 是怎么工作的？（商汤 / 快手）**
`super()` 不是「调用父类」，而是「按当前实例类型的 MRO，找到当前类之后的下一个类，返回绑定到该实例的代理对象」。无参形式靠编译器提供的 `__class__` cell 和第一个参数推断出 `super(CurrentClass, self)`。所以在多继承/mixin 里它能正确跳过已访问的类，实现协作调用；单继承里看起来才像「调父类」。

**13. 魔术方法有哪些，各自什么时候被调用？**
按类别记：构造与生命周期 `__new__` / `__init__` / `__del__`；表示 `__repr__` / `__str__` / `__format__` / `__bytes__`；比较与哈希 `__eq__` / `__lt__` / `__hash__`（定义 `__eq__` 会把 `__hash__` 置 None）；容器协议 `__len__` / `__getitem__` / `__setitem__` / `__contains__` / `__iter__` / `__next__`；属性访问 `__getattr__` / `__getattribute__` / `__setattr__` / `__get__`；数值与运算符 `__add__` / `__radd__` / `__iadd__` / `__bool__`；调用与上下文 `__call__` / `__enter__` / `__exit__`；以及 `__slots__` / `__init_subclass__` / `__class_getitem__`。

**14. __slots__ 有什么用？**
在类里声明固定的属性名，实例不再创建 `__dict__`（和 `__weakref__`），改用紧凑的槽位描述符存储。收益是内存明显下降（大量小对象时可省一半以上）且属性访问略快，还能防止拼错属性名悄悄创建出新字段。代价：不能动态加属性、需要弱引用要显式加 `'__weakref__'`、多继承时多个父类有非空 slots 会冲突、与某些依赖 `__dict__` 的序列化/ORM 不兼容。先 profile 再决定用，别默认加。

**15. 元类是什么，什么时候会用到？**
元类是「类的类」，默认 `type`，`class` 语句本质就是调用元类创建类对象。自定义 `class Meta(type)` 并指定 `metaclass=Meta`，就能在 `__new__` / `__init__` 里拦截类的创建、改写属性、自动注册子类。典型场景：ORM 收集字段生成表映射（Django Model）、接口/实现校验、插件注册、单例、自动给方法加装饰器。多数需求用 `__init_subclass__`、类装饰器或 `Protocol` 就够了，元类是「知道自己在做什么才用」的工具。

**16. Python 的反射机制是什么？（腾讯）**
运行时动态探查和操作对象与模块的能力：`getattr` / `setattr` / `hasattr` / `delattr`、`dir()` / `vars()` / `__dict__`、`isinstance` / `issubclass`、`inspect` 模块取签名和源码、`importlib.import_module` 按字符串导入、`globals()` / `locals()`。框架里常用于按配置字符串实例化类、路由分发、插件加载、序列化。代价是静态检查和 IDE 补全失效，名字拼错要到运行时才暴露。

**17. Python 里有接口吗，抽象类怎么写？**
没有 `interface` 关键字。两种主流做法：`abc.ABC` + `@abstractmethod` 定义抽象基类，子类必须实现否则无法实例化，属于名义子类型；`typing.Protocol`（3.8+，PEP 544）定义结构化接口，只要对象有对应方法就满足，属于静态鸭子类型，配合 `@runtime_checkable` 可做 `isinstance` 检查。业务代码更常用 Protocol 或直接鸭子类型。

**18. 怎么实现单例模式？**
按推荐度：① 模块级实例最 Pythonic——模块天然只导入一次（`sys.modules` 缓存），直接 `from conf import settings`；② 重写 `__new__` 缓存实例，注意 `__init__` 会被重复调用要用标志位防重；③ 装饰器/元类统一包装；④ 需要考虑并发时给创建过程加锁（双重检查）。坑：多进程各自一份内存、反序列化/`copy` 可能绕过单例、单例带可变全局状态会让测试难做，先想清楚是否真的需要全局唯一。

**19. Python 里怎么实现观察者模式？**
被观察者维护一个观察者列表（推荐 `weakref.WeakSet` 避免持有引用导致内存泄漏），提供 `attach` / `detach` / `notify`：notify 时遍历调用观察者的 `update(event)`。Python 生态里更常见的现成实现是信号库（blinker、Django signals）、事件总线、回调注册或 `asyncio` 的任务通知；同步 notify 要处理某个观察者抛异常不打断其他订阅者，异步场景可把通知投递到队列。

**20. Python 里的类型注解有什么用，会影响运行吗？**
注解（PEP 484 起）写在 `__annotations__` 里，默认**不参与运行时类型检查**、不改变执行逻辑，主要给 mypy / pyright / IDE 做静态检查和补全，可读性也更好。`from __future__ import annotations`（3.11+ 默认延迟求值方向）会把注解存成字符串，解决前向引用和导入开销。但要注意 FastAPI / Pydantic / dataclass / attrs 会在运行时读取注解做校验和序列化，此时注解是「有运行时语义」的；3.10+ 支持 `X | None`，3.12 起有 PEP 695 的 `type` 别名与新泛型语法。

## 七、内存管理与垃圾回收

**1. Python 的垃圾回收机制是怎样的？（字节跳动 / 阿里巴巴 / 百度）**
CPython 以**引用计数为主 + 分代标记清除为辅**：每个 `PyObject` 头部有 `ob_refcnt`，赋值、传参、被容器持有时 +1，名字离开作用域/被重新绑定/`del` 时 -1，归零立即释放并级联递减它引用的对象。引用计数实时、停顿小，但解决不了循环引用，所以 `gc` 模块额外追踪容器对象，用分代标记清除定期找出不可达的循环垃圾。另有 `weakref` 让缓存不延长对象生命周期。

**2. Python 的内存是怎么分配和回收的？（华为 / 字节跳动）**
≤512 字节的小对象走 `pymalloc` 三层池：`arena`（256KB，向 OS 申请）→ `pool`（4KB，同一尺寸级别）→ `block`（按 8 字节对齐的 size class 切分），避免频繁 `malloc` 和内存碎片；大对象直接调 `malloc`。释放时引用计数归零触发 `tp_dealloc`，内存**归还给池而不是立刻还给 OS**，留给后续同尺寸对象复用，所以进程 RSS 常常只涨不落。

**3. 引用计数是怎么工作的，有什么缺点？**
对象头的 `ob_refcnt` 记录有多少个引用指向它，解释器在每次绑定/解绑时由 C 层宏 `Py_INCREF` / `Py_DECREF` 维护，归零立刻调用析构并递归释放它引用的对象。缺点：① 完全无法回收循环引用（a 引用 b、b 引用 a，计数永不归零）；② 每次赋值都要读写计数，散布在解释器各处，是性能开销，在 3.13 的无 GIL 构建里还需要更复杂的原子/延迟计数；③ 池化导致内存不返还 OS，RSS 看起来像泄漏。

**4. 循环引用怎么处理？（快手 / 美团）**
靠 `gc` 模块的分代标记清除：它只追踪「能容纳其他对象引用」的容器（list/dict/set/自定义实例等 GC-tracked 对象），从根集合出发做可达性分析，把不可达的循环孤岛整体回收；int/str 这类原子对象不参与追踪。3.4 的 PEP 442 之后，即使循环里的对象带 `__del__` 也能被正确回收（此前会进 `gc.garbage` 永久泄漏）。可用 `gc.collect()` 手动触发，`gc.disable()` 关闭（只在确定无循环垃圾的短任务里才这么做）。

**5. 标记清除和分代回收分别解决什么问题？（华为 / 字节跳动 / 滴滴）**
标记清除解决的是「引用计数解决不了的循环引用」：先复制一份引用计数、把容器之间的内部引用减掉，再从根对象标记可达的，剩下就是不可达的循环垃圾。分代回收解决的是「每次都全堆扫描太贵」：基于「越年轻的对象越容易死」的弱代假说，把对象按存活时间分 0/1/2 代，新对象在 0 代高频小额回收，活下来的逐级晋升，2 代才做全量扫描，用很低的平均开销覆盖长生命周期对象。

**6. 分代回收的三代是怎么划分的，什么时候触发？**
新创建的 GC-tracked 对象进 0 代，经历一次 0 代回收仍存活就晋升到 1 代，再存活晋升到 2 代。默认阈值 `gc.get_threshold()` 是 `(700, 10, 10)`：0 代的「分配数 − 释放数」超过 700 触发 0 代回收；0 代累计回收 10 次触发一次 1 代；1 代累计 10 次触发一次 2 代（full GC）。可用 `gc.set_threshold()` 调整，`gc.collect(generation)` 手动指定代；2 代回收最贵，长跑服务要留意它造成的周期性延迟毛刺。

**7. Python 的内存池机制是什么？**
就是上面说的 `pymalloc`：按 8 字节粒度划分 size class（8/16/24…512 字节），每个 pool 只服务一种尺寸，arena 用双向链表按空闲度管理，空 arena 才整体 `free` 还给系统。好处是小对象分配 O(1)、缓存局部性好、避免 malloc 碎片；代价是内存驻留——删掉一百万个小对象后 RSS 也未必下降，因为 pool 还被其他对象占着。可用 `tracemalloc` 看真实分配，或 `malloc_trim` / 进程重启来归还。

**8. Python 有内存泄漏吗？既然有 GC 为什么还会泄漏？（阿里巴巴）**
有。GC 只保证「不可达的对象会被回收」，而泄漏往往是「对象仍然可达、但逻辑上不再需要」：无上限的全局缓存/字典、注册后未注销的回调与观察者、闭包或 `ThreadLocal` 长期持有大对象、异常 traceback 持着整个栈帧、未关闭的文件/连接/游标、C 扩展里自己 `malloc` 忘了 free。循环引用带 `__del__` 在 3.4 之前也是真泄漏，现在已修复。

**9. Python 程序的内存泄漏怎么排查和解决？（字节跳动 / 腾讯）**
排查路径：先用 `psutil` / 监控看 RSS 是缓慢单调上涨还是周期性峰值 → `tracemalloc.start()` 拍两次快照用 `compare_to` 按行定位分配源 → `objgraph.show_growth()` / `show_backrefs()` 看哪类对象在涨、谁还引用着 → `gc.get_objects()` + `gc.get_referrers()` 追引用链 → 涉及 C 扩展用 `memray` 或 `Pympler`。解决：给缓存加 `maxsize` / TTL（`functools.lru_cache(maxsize=...)`）、改用 `weakref.WeakValueDictionary`、用 `with` 确保关闭资源、异常里别长期保存 traceback、拆批流式处理、`del` 大对象后必要时 `gc.collect()`（只作兜底，不能当设计）。

**10. 单进程内存溢出（OOM）怎么解决？（腾讯）**
先区分是「峰值过高」还是「真泄漏」：峰值型改流式——逐行/分 chunk 读、生成器管道、`pandas.read_csv(chunksize=)`、用 NumPy 紧凑 dtype 或 mmap/磁盘换内存，避免 `list(df.values)` 这种整份物化，并控制并发批量大小与 worker 数；泄漏型按上一题定位。运维上还要设容器/进程内存上限加监控告警、用 `resource.setrlimit`、必要时让 supervisor 定期优雅重启，或把任务拆到多进程/多机分摊。

**11. Python 和 Java 在内存管理和 GC 上有什么区别？（字节跳动 / 华为 / 网易）**
Python 是引用计数即时回收 + 分代标记清除补循环引用，对象随用随释放、停顿小但每次赋值都有计数开销，且没有堆压缩所以有碎片；Java 是纯追踪式 GC（G1 / ZGC / Shenandoah），从 GC Roots 做可达性分析、分代或分区、并发标记与整理，有 STW 但现代收集器能压到毫秒/亚毫秒级。Java 有成熟的堆大小与 GC 参数调优体系；Python 内存交给 pymalloc 池，单个对象头开销更大（空 `object` 也要十几字节），也不轻易把内存还给 OS。

**12. Python 和 Go 的内存管理有什么区别？（字节跳动 / 阿里巴巴）**
Go 编译期做逃逸分析，能放栈的就不上堆，堆用并发三色标记 + 写屏障、按 `GOGC` 目标与 GC pacing 触发，值类型紧凑、无引用计数、天然没有循环引用问题；Python 所有对象都在堆上，靠引用计数即时回收，GIL 让计数更新不必原子化（3.13 无 GIL 构建要改用偏向引用计数等机制），另有 pymalloc 池和分代 GC 兜底。因此 Go 在高并发服务里内存与 GC 停顿更可控，Python 的对象开销和 GIL 是主要代价。

**13. Python 和 C 的垃圾回收机制一样吗？（中兴 / 快手）**
完全不一样。C 没有 GC：栈上局部变量随函数返回自动失效，堆内存必须 `malloc/free` 手动配对，漏了就泄漏、重复释放或悬垂指针就是未定义行为；Python 由解释器自动管理（引用计数 + 分代 GC + 内存池），开发者只操作名字绑定。要注意 Python 对象底层仍是 C 的 `malloc`，C 扩展里手写内存管理出错照样会泄漏或崩溃，GC 管不到那部分。

**14. 弱引用 weakref 是什么，解决什么问题？**
弱引用指向对象但**不增加引用计数**，对象被回收后取弱引用得到 `None`（或触发注册的回调）。它解决「想关联/缓存一个对象，又不希望因此让它永生」的问题：缓存用 `WeakValueDictionary`、观察者列表用 `WeakSet` 避免持有订阅者、对象间双向关联避免循环引用、以及 `weakref.finalize` 做可靠的清理钩子。限制：目标必须支持弱引用（要有 `__weakref__` 槽），`list` / `dict` / `int` / `str` / `tuple` 都不行；`weakref.proxy` 可让用法更透明。

**15. Python 的堆和栈是怎么使用的？（华为 / 美团）**
和 C/C++ 不同：**所有 Python 对象本体都在堆上**（由 pymalloc 管理），局部变量只是帧里的名字/指针数组，指向堆对象。所谓「栈」主要是解释器的执行栈——每次调用压入一个帧对象（`PyFrameObject`，3.11 起帧数据也分配在堆上的专用 chunk 里），返回时弹出；C 层还有原生调用栈。因此闭包能让本该出栈的局部变量继续存活，异常 traceback 会持有整条帧链及其引用的大对象，这是常见的内存滞留原因。

**16. del 一个变量会立即释放内存吗？**
不一定。`del x` 删除的是**名字绑定**，使对象引用计数 -1；只有减到 0 时对象才会被析构并释放，若还有其他变量、容器、闭包、traceback 引用它，对象完全不受影响。即便归零，小对象内存通常也只回到 pymalloc 池复用而不还给 OS，RSS 不会立刻下降；涉及循环引用时还要等 `gc` 那一轮。想真正释放大块内存，通常是删掉所有引用并让池/arena 整体空闲，必要时重启进程。
